# 2.1.5 이미지 사용량 구현·검증 기록

상태: 구현·최종 수업 회귀·로컬 통합 검증 통과, develop 인계 중. 운영·스토어 미배포.
기준 소스: origin/develop f704829c94c917954244cbfc637191d0a4fb377c (2.1.2+8).
표시 버전: **2.1.5+9**. +9는 소스의 로컬 빌드 번호다. 실제 Play/TestFlight 파이프라인은 별도 번호를 예약·주입한다. 배포 태그나 스토어 번호를 발급하지 않았다.

## 정책

| 항목 | 무료 | 프리미엄 |
| --- | ---: | ---: |
| 총 이미지 보관 | 100MB | 1GB |
| 하루 신규 업로드 | 30MB | 500MB |
| 수업당 이미지 합계 | 100MB | 100MB |
| 하루 이미지 전송 | 50MB | 1GB |
| 월 이미지 전송 | 500MB | 20GB |

MB/GB는 십진 bytes, 기간은 서버 KST다. 새 수업은 자료를 받기 전 일·월 여유와 준비 예산을 확인한다. 진행 중인 동일 수업의 중지·재개·재연결은 한도 때문에 중단하지 않으며 초과 제공량을 별도로 기록한다. 절대 청구 상한을 보장하는 기능은 아니다.

관리자 임시 증액 API는 역할·최근 인증·유한 용량·대상 기간·만료·사유·멱등키·감사를 검사한다. 무제한 우회나 자동 추가 결제는 없다. 새 상품 안내는 무료/프리미엄만 남기고 과거 Plus 권한·영수증 복원은 격리 어댑터로 보존한다. 구독 종료·가격·실제 과금은 변경하지 않는다.

## 수업·디스플레이에서 수정한 범위

- 준비 시작 전 사용량 gate와 서버 admission을 확인하고, 등록된 이미지의 준비 예약 뒤에 TV 요청/인증 이미지 수신을 시작한다.
- 준비 schema2와 이미지 사용 protocol1을 추가하고 기존 schema1 준비 경로를 유지한다. 컨트롤러만 쓰는 수업과 검증된 기존 inline 이미지도 지원한다.
- 새 한도 적용 계정의 시작은 서버 commit으로 같은 session/snapshot을 게시한다. pending 요청은 같은 ID로 복구하며 클라이언트 직접 시작으로 우회하지 않는다.
- managed 이미지 업로드·렌더·precache·브랜드·프로필·기존 AI 이미지 산출물에 인증/원장 경로를 연결했다. 이미지 압축이나 품질 변경은 없다.
- 재연결은 기존 물리 TV binding으로 확인한다. 다른 TV 재페어링은 기존 수업 참가자로 간주하지 않는다.
- 준비 오류 안내가 TV 목록과 공통 영역에 중복 표시되던 문제를 수정했다.

타이머 시간 계산·진행·pause/resume/seek 제어 구현은 수정하지 않았다. 준비/시작 진입점, 인증 미디어 전달, 해당 접근 규칙을 수정한 것이다. 기존 비전환 계정은 legacy 경로를 유지한다.

## 적용 경계

명시적 동의, 검증된 inventory/token-free 자산, 새 프로토콜과 rules 준비가 갖춰진 계정만 새 정책에 전환할 수 있다. 이미 활성 legacy 수업은 전환을 거부해 유지한다. 압축·과거 파일 삭제·토큰 철회·캐시 최적화·자동 migration은 없다.

신규 API/trigger는 개발 프로젝트와 demo에서만 노출하고 운영 cloud-board-stationd에서는 omit한다. 기본 정책은 off이며 운영 데이터/설정·개발 Firebase·main·스토어에 배포하지 않았다. 개발 배포용 source 목록만 새 API에 맞게 갱신했다.

기존 재사용 token URL과 구버전 직접 다운로드를 전부 제어하는 기능으로 보고하지 않는다. 웹 CORS 실서비스 origin은 명시적으로 설정·검증해야 하며 자동 wildcard 허용하지 않는다.

| 전환 복구 경합 | 4 scenarios 통과 | 실제 로컬 FS/RTDB, 12 동시 setter와 복구 후 수업 보호 |

테스트 묶음은 일부 겹치므로 합계로 집계하지 않는다. 최초 필수 VM 검사에서 10개 실패를 숨기지 않고 보존했고, 명시적 legacy 사용량 fixture와 새 protocol 기대값을 보완했다. 관련 41개 focused 검사와 분석도 통과했다. 제품의 fail-closed 검사를 약화하거나 테스트를 삭제/skip하지 않았다.

공개 API 흐름은 실제 로그인/폐기 token,10485759B 업로드·수신,saveWorkout callable와 인증 클라이언트 readback,준비→lease→commit,실제 중지/재개/완료,초과 후 같은 수업 보호,다른 TV 재페어링 차단을 확인했다. 빈 계정 inventory/정책/권한/페어링/TV ready 영수증/한도 소진은 Admin local fixtures다. 실제 Flutter 앱이나 물리 TV 준비가 성공한 것으로 보고하지 않는다.

초기 로컬 config 경로 오류와 공유 Storage 임시 폴더 충돌을 기록·수정했다. 최종 emulator는 고유 TMPDIR와 명시적 demo 프로젝트만 사용했다. 도구는 Node22.21.1 arm64,JDK21,Flutter3.47.8이다. 새 generated annotation이 없어 build_runner는 실행하지 않았다. dependency/lockfile 업그레이드는 없다.

## 미확인 및 인계

실제 2.0.5/2.1.5 앱·물리 TV 혼합 수업, 배포된 v2 버퍼 응답과 실제 브라우저 origin, 실제 store/provider, 자동 RTDB trigger 전달은 확인하지 않았다. 로컬 emulator region 제약으로 완료는 실제 callable get 대사를 통해 검증했으며 자동 event delivery 성공으로 주장하지 않는다. 기존 활성 legacy 전환도 별도 migration이 필요하다.

최종 commit/PR과 추가 root 결과는 develop 인계 시 이 기록에 연결한다. 설계와 구현 중 보완된 상세 계약은 [2.1.5-usage-contract.md](2.1.5-usage-contract.md)를 참조한다.

## 로컬 재현

Node22와 JDK21, Firebase CLI를 준비하고 `npm ci --prefix functions`를 실행한다. 앱은 .fvmrc의 Flutter3.47.8을 사용한다. 실제 서비스 대신 아래 **demo 프로젝트와 명시적 config**만 사용한다. 동시 에뮬레이터의 Storage 임시 파일 충돌을 피하려고 TMPDIR를 분리한다.

```sh
mkdir -p /tmp/cloudboard-2-1-5-usage/root-emulator-tmp
TMPDIR=/tmp/cloudboard-2-1-5-usage/root-emulator-tmp/ \
CLOUDBOARD_MEDIA_EMULATOR_BASE_URL=http://127.0.0.1:5008/demo-cloudboard-usage-integration/asia-northeast3/cloudboardMedia \
firebase emulators:start --project demo-cloudboard-usage-integration \
  --config firebase.image-usage-emulator.json --only auth,firestore,database,storage,functions
```

다른 터미널에서 다음을 실행한다. 스크립트는 정확한 demo 프로젝트와 loopback port가 아니면 실행을 거부한다. 테스트 데이터는 local fixtures이며 실제 TV 영수증이 아니다.

```sh
GCLOUD_PROJECT=demo-cloudboard-usage-integration \
FIRESTORE_EMULATOR_HOST=127.0.0.1:8188 \
FIREBASE_DATABASE_EMULATOR_HOST=127.0.0.1:9188 \
FIREBASE_STORAGE_EMULATOR_HOST=127.0.0.1:9288 \
FIREBASE_AUTH_EMULATOR_HOST=127.0.0.1:9098 \
node functions/test/media-gateway-runtime-e2e.mjs
node tool/class_start_regressions.mjs vm
node tool/class_start_regressions.mjs chrome
flutter build web --debug --no-pub --dart-define=FIREBASE_ENV=development
```
