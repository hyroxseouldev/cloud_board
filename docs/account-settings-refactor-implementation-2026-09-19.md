# 계정 설정 분리 구현 및 DB 전환 안내

대상: develop · STA-16 후속 · 2026-09-19

## 구현 범위

- 편집 상세 로더에서 계정 설정 합성을 제거했다. 신규 초안도 계정 설정 조회를 기다리지 않는다.
- `WorkoutContent`(콘텐츠), `WorkoutPreferences`(공통 설정), `WorkoutPlaybackSnapshot`(확정된 재생 데이터)을 분리했다.
- `WorkoutDocument`가 Firestore 콘텐츠 전용 직렬화/구형 디코딩을 담당한다. 기존 `Workout`은 편집 화면·타이머·구형 TV 프로토콜의 호환 객체로 남아 있다. UI 전체를 이 타입에서 한 번에 전환한 것은 아니다.
- 원격 시작은 기존 서버 확인 정책을 유지하고, 로컬 재생·슬라이드 미리보기·브리핑/소리 테스트는 별도 설정 해석 경로를 사용한다. 설정 조회 실패를 미리보기 성공으로 표시하지 않는다.
- 공통 설정 저장은 상세 캐시 전체를 무효화하지 않는다. 실행 중 로컬/원격 수업의 스냅샷은 그대로 유지한다.
- 설정은 UID별 30초 캐시와 동시 요청 공유를 사용한다. 원격 시작/명시적 새로고침은 캐시를 우회한다. 인증 변경 시 캐시를 해제한다.
- 계정 설정 UI 초안은 `WorkoutPreferences`를 직접 사용한다. 카운트다운 미리보기 위젯에 전달할 때만 호환용 Workout을 만든다.
- 저장 API가 업로드된 이미지 URL과 새 revision을 반환한다. 성공 후 초안·기준값에 반영해 같은 로컬 파일의 재업로드를 막는다.
- 다른 기기와 revision이 충돌하면 입력을 유지하고, 최신 설정을 다시 불러올 수 있다.

## 새 저장 형식과 호환 단계

```text
users/{uid}/settings/workout
  schemaVersion: 1
  revision: 1, 2, ...
  updatedAt: 서버 시각
  contentOnly: false → 관리자 이관 도구만 true로 전환
  preferences: {brandL, brandR, soundTheme, ... , countdown}
```

분석 문서의 설정 필드는 `preferences` 객체 아래에 모았다. revision 등 저장 메타데이터가 UI 값이나 구버전 호환 필드에 섞이지 않도록 하기 위해서다.

기본 호환 단계(`contentOnly: false`)에서는 새 문서를 원본으로 사용하면서 사용자 문서의 `workoutSettings`에도 같은 값을 한 방향으로 기록한다. 기존 워크아웃의 설정 필드는 DB의 원래 값을 유지하며, 편집/미리보기에서 합성된 값을 재저장하지 않는다. 신규 워크아웃에도 구버전이 읽을 기본 필드는 임시로 남는다.

새 문서가 생긴 계정에서 구버전이 옛 `workoutSettings`를 직접 변경하는 요청은 규칙으로 차단한다. 구버전은 저장 오류를 볼 수 있으므로 해당 계정 운영 기기에는 호환 앱 업데이트를 먼저 안내해야 한다. 기존 설정 조회와 일반 프로필 수정은 유지된다.

`contentOnly: true`부터는 워크아웃 문서에 `schemaVersion: 2`와 콘텐츠 필드만 쓴다. 구버전 워크아웃 쓰기도 규칙에서 차단한다. 콘텐츠·요약 저장은 트랜잭션으로 묶고, 이관 단계와 기존 문서를 확인한다. 이 때문에 저장 시 확인용 읽기가 추가된다. 전체 작업의 비용 절감률이나 속도 개선률을 실측했다고 주장하지 않는다.

새 앱은 `settings/workout` 권한 규칙이 필요하다. **새 규칙 배포 없이 이 코드로 운영 서버에 연결하면 설정 조회/저장이 실패한다.** 이번 작업에서는 운영 규칙을 배포하지 않았다.

## 이관 도구

파일: `functions/scripts/migrate-workout-settings.mjs`

Application Default Credentials와 해당 프로젝트의 필요한 관리자 권한을 사용한다. 인증 정보는 출력하지 않는다. 기본값은 읽기 전용이다. 운영 전체 계정보다 지정 계정으로 먼저 진행한다.

```sh
# 저장소 루트에서, 조회만
node functions/scripts/migrate-workout-settings.mjs \
  --project cloud-board-stationd --uid ACCOUNT_UID

# 새 설정 문서 준비 + 구버전 조회용 미러. 저장소 밖의 비공개 백업 경로 필요
node functions/scripts/migrate-workout-settings.mjs \
  --project cloud-board-stationd --uid ACCOUNT_UID \
  --apply --backup-dir /absolute/private/backup-directory

# 모든 운영 기기가 호환 앱으로 전환된 것을 확인한 계정만 실행
node functions/scripts/migrate-workout-settings.mjs \
  --project cloud-board-stationd --uid ACCOUNT_UID \
  --apply --backup-dir /absolute/private/backup-directory \
  --finalize --confirm-compatible-clients
```

`--uid`를 생략하면 계정 전체를 조사한다. 기본 보고서는 계정별 상태/워크아웃 수/설정 종류 수다.

- 이미 공통 설정이 있는 계정: 해당 값으로 준비한다.
- 모든 구형 수업의 설정이 같은 계정: 그 값을 계승한다.
- 설정이 다른 수업이 섞인 계정: `needs-selection`으로 건너뛴다. 앱의 계정 공통 설정 화면에서 값을 확정한 뒤 다시 실행한다.
- 수업 없는 계정: 옛 카운트다운 기본값과 신규 앱 기본값을 사용한다.
- 손상/알 수 없는 설정: 해당 계정을 오류로 기록하고 자동 이관하지 않는다.

실제 변경 전에 원본과 문서 버전을 권한 0600 파일로 저장한다. 백업 후 내용이 바뀌면 덮어쓰지 않고 중단한다. finalize는 먼저 구버전 쓰기를 차단하는 표식을 설정하고, 문서별 버전을 확인해 구형 필드를 삭제한다. 문서 정리는 현재 원본을 별도로 백업한다. 진행 중 수업/세션·이미지 파일은 수정하지 않는다.

중간 실패 시 보고서와 백업을 확인한 뒤 동일 옵션으로 재실행할 수 있다. 이미 확정한 공통 값을 덮어쓰지 않으며, finalize 완료 계정의 revision을 재실행만으로 올리지 않는다. 삭제 진행 중인 계정은 건너뛴다.

대규모 계정의 준비 단계는 전체 워크아웃 쿼리를 트랜잭션에서 다시 확인하므로 시간/트랜잭션 한도에 도달할 수 있다. 이 경우 해당 계정을 오류로 남긴다. 규모별 분할 이관은 별도 검토가 필요하다.

## 검증 및 아직 실행하지 않은 것

- Flutter 최종 관련 자동 검증: 55개 통과(콘텐츠 경계, 계정 설정 UI, 편집, 브리핑, 파일럿 재생, 목록 요약·로딩). 설정 로딩 표시에서 발견한 미리보기 4px overflow를 수정했다.
- Node 이관 정책 검증: 6개 통과.
- 로컬 Firestore 에뮬레이터: 권한, revision 충돌, 구버전 쓰기 차단, 관리자 전환 표식, 삭제 잠금 검증 통과.
- 동일 에뮬레이터: dry-run → 백업/prepare → 혼합 설정 계정 제외 → finalize → 반복 실행 검증 통과. 콘텐츠와 생성 시각·일반 프로필 필드 보존 확인.
- Flutter 정적 분석: 오류 없음.
- 운영 DB 조회/이관·규칙 배포, 앱 빌드·시뮬레이터 실행, main 병합·운영 배포는 하지 않았다.

목록의 전체 다운로드/상세 예열 정책과 이미지 참조 기반 정리는 분석 문서에서 분리한 후속 단계로 남긴다. 현재 오프라인 목록·검색·예약 동작을 유지한다. 변경 전후 실기기 성능 수치는 아직 측정하지 않았다.

구형 필드 정리 후에는 구버전 바이너리로 단순 롤백할 수 없다. 호환 앱을 유지하거나, 백업의 설정 필드만 현재 문서 버전과 비교해 복구해야 한다. 전체 콘텐츠를 과거 백업으로 일괄 덮어쓰는 복원은 하지 않는다. 자동 롤백 도구는 이번 범위에 포함하지 않았다.
