# 템플릿 렌더링과 저장 자산 재사용

STA-123과 STA-124의 변경은 작은 템플릿 카드의 원본 이미지 메모리와 변경 없는 워크아웃 저장의 PNG 준비 작업을 줄인다. 실기기 프로파일 측정은 사용자가 추후 진행하기로 했다. 아래 캐시 용량은 실제 프로세스 RSS나 GPU 메모리 측정값이 아니다.

## 미리보기와 내보내기

- 카드가 스크롤 뷰포트와 겹칠 때만 `WorkoutSlidePreview`를 생성한다. 화면 밖으로 이동하면 미리보기를 해제한다. 일곱 프리미엄 템플릿의 카드와 선택 동작은 유지한다.
- 디코딩 너비는 고정 1920 캔버스 내부가 아닌 실제 표시 영역에서 계산한다. contain/cover, 기기 픽셀 비율, 표시 확대를 반영하고 64px 단위로 묶으며 원본 너비 이하로 제한한다.
- 축소한 이미지는 원본 좌표 영역에 그린다. 글자 위치·폰트·편집 영역·타이머 배치는 기존 좌표계를 그대로 사용한다.
- PNG 내보내기는 별도로 원본 해상도를 요청하고 기존 1920×1080 결과를 만든다. 회귀 테스트는 여섯 3840×2160 원본과 돌파 원본의 결과를 직접 그린 기준 이미지와 픽셀 단위로 비교한다.

| 캐시 | 보관 예산 | 퇴출 |
| --- | --- | --- |
| 표시 크기 미리보기 | RGBA 픽셀 기준 16 MiB | 예산 초과 시 가장 오래 사용하지 않은 항목부터 제거 |
| 전체 해상도 내보내기 원본 | RGBA 픽셀 기준 64 MiB | 예산 초과 시 가장 오래 사용하지 않은 항목부터 제거 |

두 캐시는 OS 메모리 부족 알림 때 비운다. 실패한 요청은 제거하여 다음 요청이 디코딩을 다시 시도하게 한다. 같은 키의 진행 중 요청은 하나로 합친다.

캐시와 호출자는 별도 `ui.Image` 핸들을 가진다. 호출자는 `clone()`으로 받은 핸들을 소유하고, 화면 종료 시 마지막 프레임 이후 또는 내보내기 완료 시 해제한다. 캐시가 먼저 퇴출되어도 사용 중인 미리보기·내보내기의 핸들은 유효하다. 예산은 캐시가 보관하는 픽셀 버퍼를 기준으로 하며, 사용 중인 클론과 순간적인 디코딩 버퍼까지 포함한 전체 메모리 상한은 아니다.

## 저장된 PNG 재사용

`WorkoutModule`과 DTO의 선택 필드 `designFingerprint`는 `v1:<visual SHA256>:<asset SHA256>` 형식이다. 시각 해시는 기존 렌더 키와 같은 입력 및 `slideDesignRendererVersion`을 사용한다. 제목·본문·디자인 스타일·색상·배치·글꼴 설정·타이머 및 세트 표시/영역을 포함한다. 이미지에 그려지지 않는 양의 타이머 시간 변경, 모듈 ID, 폴더 변경은 시각 키를 바꾸지 않는다. 폰트 자산이나 렌더러 자체의 출력이 바뀌면 렌더러 버전도 올려야 한다.

시각 키가 일치해도 현재 Firebase 버킷의 `users/<uid>/workouts/<workoutId>/images/<asset SHA256>`에 속한 정확한 자산인지 확인한다. 다른 이미지 URL로 바꾼 뒤 예전 fingerprint만 남아 있는 경우에는 재사용하지 않는다. 확인된 다운로드 URL을 갱신하여 토큰이 바뀐 경우도 반영한다.

자산 확인은 최대 세 건씩 병렬 수행한다. 렌더링이 필요한 슬라이드는 순차적으로 준비하여 큰 PNG 버퍼가 한꺼번에 생성되는 것을 막는다. 최종 업로드가 성공한 뒤 시각 해시와 자산 해시를 연결한다.

- fingerprint가 없거나 이전 버전이면 한 번 준비한 뒤 새 메타데이터를 저장한다.
- URL이 없거나 자산이 삭제되었으면 다시 준비한다. 삭제된 자산의 오래된 업로드 캐시도 제거한다.
- 계정·워크아웃·버킷이 다르면 해당 범위의 새 자산을 준비한다.
- 권한 및 네트워크 실패는 저장 실패로 전달한다. 없는 자산만 복구 대상으로 처리한다.
- 앱 재시작으로 PNG 메모리 캐시가 비어도 저장된 fingerprint와 유효 자산으로 재사용한다.

Firestore의 모듈 데이터 허용 정책과 소유권 규칙은 유지한다. 구버전 DTO는 이 필드를 생략할 수 있다. 현재 DTO와 출시된 1.0.0+2의 불변 fixture를 모두 규칙 에뮬레이터에서 재생하여 두 스키마의 생성·수정·복제와 소유권/롤백을 검증했다.

## 검증과 측정 도구

렌더링·원본 품질·캐시 수명·갤러리 편집·저장 자산·DTO 내보내기 관련 최종 테스트 88개와 해당 코드 정적 분석이 통과했다. 1/8/9/30장의 변경 없는 저장과 서비스 재생성 후 저장에서 이미지 준비 및 신규 업로드 호출이 0회임을 검증했다. 시각 내용 한 장만 수정할 때에는 해당 장만 준비한다.

`tool/sta122_storage_profile.dart`의 `profileDesignSaves()`는 기준 커밋 7f8e2b3에서도 실행할 수 있다. 30개의 서로 다른 디자인으로 실제 그리기·PNG·Base64 경로를 실행하고, 외부 Storage만 메모리 구현으로 대체한다. 첫 저장 및 폴더만 바꾼 두 번째 저장의 시간을 반환한다. `PngPreparationMicros`는 저장 시작부터 첫 업로드 호출까지의 준비 구간으로, PNG 인코더만 분리한 시간이 아니다. 준비할 이미지가 없으면 0이다. 원격 업로드와 실서비스 네트워크 시간은 측정하지 않는다.

실기기 재현은 `tool/sta122_device_profile.dart`를 별도 앱 식별자로 profile 모드에서 실행한다. 원본 커밋과 변경 브랜치에 같은 도구 파일을 사용하고 같은 기기·화면·빌드 조건에서 비교해야 한다. 실기기 첫 진입·세 번 왕복의 RSS 및 긴 프레임 수치는 아직 수집하지 않았다.
