## 연결 경고와 재생 지속성

현장 제보는 **태블릿 화면 꺼짐 후 디스플레이 연결 끊김 안내와 슬라이드 되감김이 함께 발생했다**는 것이다. 실제 사고를 재현하거나 원인을 하나로 확정한 상태는 아니다.

기존 경고는 컨트롤러의 Firebase 연결 상태로 디스플레이 문제를 안내했다. 지금은 ‘컨트롤러의 서버 연결이 끊겼습니다. 연결 복구 후 수업 상태를 확인해 주세요.’로 출처를 명시한다. 디스플레이의 실제 오프라인 여부는 등록 기기 상태와 함께 현장에서 확인해야 한다.

서버 세션 anchor는 자연스러운 운동/휴식 전환 때 바뀌지 않는다. 컨트롤러가 잠기거나 전체 조작 화면이 사라져도 디스플레이가 같은 기준으로 진행한다. 정지 명령은 이미 경과한 운동 단계와 남은 시간을 함께 저장한다. 여러 기기의 명령 충돌은 기대 revision이 다르면 거절하며 자동으로 새 상태에 재적용하지 않는다.

앱 명령은 기존 `notificationCommand` 만료 규칙을 재사용한다. SDK 쓰기가 잠시 대기하더라도 서버가 만료된 명령을 거절한다. 시간 초과 직전 서버 반영 후 응답만 유실될 수 있으므로, 오류는 ‘결과 확인 실패’로 안내하고 서버 스트림을 따른다. 성공을 낙관적으로 확정하지 않는다. 자연 종료는 현재 세션이 유지될 때 컨트롤러가 완료 처리하며, 모든 컨트롤러가 잠들어 있더라도 디스플레이는 시간 기준으로 끝난다. 복귀한 컨트롤러는 경과 종료된 세션을 정리한다.

## iPad 시스템 제어 사용 방식과 제약

사진의 음악용 미디어 카드를 점유하는 방식 대신 **수업 전용 단축어**를 제공한다. 컨트롤러는 원격 수업을 Now Playing에 등록하지 않으므로 같은 기기의 음악 앱 제어와 분리된다. iOS 무음 WAV 반복 재생과 전용 플레이어, background audio 선언을 제거했다. 로컬 시험 재생의 기존 효과음과 전면 미디어 명령 코드는 유지한다.

1. 앱에서 로그인하고 연결 수업을 시작한다.
2. 단축어 앱에서 Cloud Board의 ‘연결 수업 조작’을 추가하고 동작을 선택한다.
3. 지원되는 OS의 제어 센터에 해당 단축어를 추가한다. 일시정지·재개·다음/이전 슬라이드를 각각 배치할 수 있다.
4. Android 기존 알림의 이전/다음은 **운동 단계**, 신규 iOS 단축어의 이전/다음은 **슬라이드** 단위다. 앱 버튼의 기존 의미를 바꾸지 않았다.

App Intent는 현재 로그인 계정·고정한 수업 ID를 다시 검증하고, 서버에서 읽은 ETag로 조건부 쓰기를 한다. 네트워크 실패·수업 교체·종료·동시 수정은 실패로 반환하며 오프라인 쓰기를 쌓지 않는다. Flutter→네이티브에는 계정/수업/기기 식별자와 구간 길이만 전달하고 인증 토큰은 저장하지 않는다. 토큰은 실행 시 네이티브 Firebase Auth에서 얻는다.

**실제 iPad에서 단축어 검색 노출, 잠금 중 인증 정책, 앱 프로세스 재시작, 음악 동시 사용을 아직 검증하지 않았다.** 전용 WidgetKit Control 위젯이나 큰 미디어 카드 UI를 추가한 것은 아니다. 제어 센터에서 단축어 실행을 지원하지 않는 OS에서는 단축어 앱과 앱 내부 미니 바를 사용한다. 강제 종료 후 제어가 항상 보장된다고 안내하지 않는다.

근거: [Apple App Intents 소개](https://developer.apple.com/videos/play/wwdc2022/10032/), [제어 센터에서 단축어 실행](https://support.apple.com/guide/shortcuts/run-shortcuts-from-control-center-apd06a9201d4/ios).

## 병합 후 시뮬레이터 시작 오류 수정

2026-09-17 사용자가 iPad 시뮬레이터에서 수업 시작 불가를 제보했다. 준비창의 시작 버튼을 누르면 홈에 머물렀으며, 실행 로그의 스택은 `PlaybackRealtimeDataSource.start()`의 `.info/connected.get()`에서 `firebase_database/permission-denied`가 발생했음을 확인했다. 앞선 자동 테스트는 순수 명령 계산을 검증했지만 Apple SDK의 메타데이터 조회 차이를 검증하지 못했다.

- `.info/connected` 및 `.info/serverTimeOffset`를 기존 SDK 이벤트 스트림의 첫 값으로 읽도록 수정했다. 3초 응답 제한을 두고 오프라인 거부·등록 확인·명령 만료 검사를 유지한다. 데이터베이스 권한을 넓히지 않는다. [Firebase 공식 메타데이터 관찰 예시](https://firebase.google.com/docs/database/ios/offline-capabilities#detecting_connection_state).
- 홈의 수업 명령 실패가 아무 안내 없이 끝나지 않도록 오류 안내를 추가했다.
- 실제 실행 중인 iPadOS 26.2 시뮬레이터에 Flutter hot reload로 적용해 시작 → 카운트다운 → 재생 → 일시정지 → 재개 → 자연 종료·홈 복귀를 확인했다. 온라인 디스플레이가 없는 해당 시뮬레이터 수업만 대상으로 확인했으며 외부 디스플레이 재생 검증은 남아 있다.
- 메타데이터의 `get()`은 거절되고 SDK 이벤트만 전달되는 회귀 테스트에서 시작·정지·진행 세션 조회, 오프라인 명령 차단, 미등록 대상 차단을 검증했다. 시작 실패 안내·재시도 UI 테스트와 정적 분석도 통과했다.

## 2026-09-18 STA-5 정정: 슬라이드 내부 시간 탐색

사용자 검수에서 터치로 슬라이드 시작점 이동은 되지만 같은 슬라이드 안의 시간 이동이 안 된다는 피드백을 받았다. 위 CLY-9(현재 STA-5)의 1차 범위를 대체한다.

- 진행 막대 터치·드래그는 해당 슬라이드 안의 **초 단위 위치**를 선택한다. 최소 표시 폭과 구간 사이 여백을 반영하고 운동·휴식·세트 전체에 걸쳐 단계와 남은 시간을 계산한다.
- 드래그 중 핸들을 갱신하고 손을 놓을 때 명령을 한 번 전송한다. OS가 포인터를 취소하면 이동하지 않는다. 오른쪽 끝은 마지막 1초로 제한해 탐색만으로 즉시 종료하지 않는다.
- 원격 이동은 전체 단계 길이가 아니라 선택한 남은 시간을 전달한다. 일시정지/재생 상태, 실패 후 서버 위치 복원, 잠금·연결 끊김·처리 중 입력 차단을 유지한다. 캐러셀·점 버튼은 기존 슬라이드 시작점 이동을 유지한다.
- `workout_timeline_seek_test.dart`, `pilot_playback_regression_test.dart`, `workout_control_panel_test.dart`: **17개 통과**. 단일 슬라이드 드래그 핸들/터치, 불균등 구간, 취소, 중복 전송, 단계 경계/양 끝, 원격 전달 값, 정지 유지/실패 복구 검증.
- 전체 Flutter 정적 분석 통과. 앱 재빌드·실기기 실행·배포는 수행하지 않았다. Android/iPad와 연결 디스플레이에서 실제 위치 동기화는 검수 필요.
