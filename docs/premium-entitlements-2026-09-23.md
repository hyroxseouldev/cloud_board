# 플랜별 디스플레이 권한 반영 — 2026-09-23

기준 문서: [Linear 구독 플랜 전략](https://linear.app/clyrdev/document/8e20f110dfa5)

## 적용 내용

- 프리미엄: 디스플레이 등록 및 동시 활성화 제한 없음. 프로필에 `CloudBoard 프리미엄`, `디스플레이 무제한` 표시.
- 플러스: 등록 목록은 유지하고 동시에 한 디스플레이만 활성화. 다른 화면을 켜면 기존 화면을 끄고, 진행 중인 세션의 위치·일시정지 상태를 유지한 채 재생 대상을 변경.
- 신규 플랜 권한을 명시하지 않은 기존 계정은 기존 제한을 유지. 권한 누락을 무제한으로 해석하지 않음.
- 프로필은 구독 권한 revision 변경 시 다시 읽음. 이용 기간은 종료 시각 직전 날짜를 로컬 시간으로 표시.

## 저장 및 호환 방식

별도 테이블/컬럼 추가 없이 기존 구독 `display_limit`에 명시적 구분을 저장한다. `-1`은 프리미엄, `1`은 플러스, 다른 양수는 기존 플랜이다. 결제 가격과 상태, 이용 기간은 변경하지 않았다.

Firebase 권한에는 `plan`, `displaysUnlimited`, `maxActiveDisplays`를 기록한다. 구버전 읽기 호환을 위한 프리미엄 `displayLimit`은 2147483647이지만, 새 서버의 프리미엄 제한 판정은 이 숫자가 아닌 명시적 무제한 필드를 사용한다. 구버전 앱 자체에 남은 표시/등록 제한은 앱 업데이트가 필요할 수 있다.

즐겨찾기 및 대기화면의 플랜 메타데이터도 함께 생성하지만, 즐겨찾기 3개 제한과 대기화면 편집 권한의 실제 강제 적용은 이번 변경에 포함하지 않았다. 현재 라이브러리는 로컬 저장이므로 계정 단위 제한에는 별도 동기화 설계가 필요하다.

## 운영 반영

- 대상 계정: `stationdofficial@gmail.com`, `vividxxxxx@gmail.com`.
- 두 계정의 Neon 구독 값을 프리미엄으로 변경하고 감사 이력을 기록했다. RTDB와 Firestore 권한 및 프로필을 함께 갱신하고 재조회로 확인했다.
- 만료 시각 `2999-12-31T15:00:00.000Z` 유지: 한국 시간으로 2999년 12월 31일까지 이용 가능.
- `cloudboardAuth`, `cloudboardPairDisplay`, `cloudboardSetDisplayState` 함수 및 RTDB 규칙 배포 완료. 세 함수 모두 ACTIVE 확인.
- 기존 `ENTITLEMENT_SYNC_ENABLED=false` 설정 유지. 이번 두 계정만 명시적으로 동기화했으며, 향후 동기화 코드도 같은 플랜 판정 함수를 사용한다.
- 함수 배포 CLI는 빌드 이미지 정리 정책 미설정으로 마지막 단계에서 경고/실패 종료했으나, 세 함수의 배포 및 ACTIVE 상태는 별도로 확인했다. 정리 정책은 변경하지 않았다.
- 최초 반영 후 iPad 시뮬레이터 Debug 재빌드·실행 성공. 사용자 확인 후 앱과 웹 저장소의 개발 → 메인 병합 및 배포 진행을 승인받았다. 구독 서버 변경은 웹 저장소 develop에도 반영하며, 앱 배포 결과는 해당 메인 커밋의 GitHub Actions에서 확인한다.

## 검증

- Flutter 정적 분석 통과, 관련 프로필·권한·페어링·수업 시작 테스트 12개 통과.
- 백엔드 TypeScript 빌드와 웹 타입 검사 통과, 신규 플랜 단위 테스트 3개 통과.
- Firebase 에뮬레이터 검증 42개 통과: 프리미엄 5대 등록, 플러스 동시 활성화 요청 시 1대 유지, 화면 교체 시 일시정지 유지, 클라이언트 직접 제한 우회 차단 포함.
- 실제 두 계정의 DB 플랜 값, RTDB/Firestore 무제한 표시, revision 및 만료 시각 일치 확인.
- 배포 전 Flutter 전체 테스트에서 이전 글자 크기를 기대하던 카운트다운 검증 1건을 발견해 새 디자인 기준으로 수정했다. 나머지 306개는 통과했고, 수정 후 카운트다운 테스트 9개가 통과했다.
