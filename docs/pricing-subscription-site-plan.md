# 클라우드보드 가격 정책 및 구독 사이트 기획 초안

작성일: 2026-09-16
상태: 검토용 제안. 가격·운영 정책 미확정. 구현·결제 활성화·배포는 포함하지 않는다.
기준: 현재 develop 소스, 기존 `docs/cloudboard-monetization-plan.md`, CloudFit 공식 사이트.

## 1. 추천 방향

초기 고객은 한 매장에서 1~3개 화면으로 그룹 수업을 진행하는 대표·코치다. 핵심 가치는 운동 순서와 시간을 화면으로 전달하고 코치가 수업을 제어하는 경험이다.

> 수업 진행은 화면에, 코치는 회원에게.
>
> 워크아웃과 타이머를 준비하고, 연결된 매장 화면에서 수업을 진행하세요.

첫 출시는 **14일 무료 체험 + Pro 단일 유료 플랜 + 화면 확장 상담**으로 단순하게 한다. 체험 카드와 유료 카드로 안내하되 체험을 영구 무료 플랜처럼 표현하지 않는다. 무료 체험 시작에는 카드를 요구하지 않고, 종료 후 사용자가 명시적으로 구독할 때만 결제한다.

## 2. 참고 서비스에서 가져올 구조

CloudFit 홈페이지는 실제 수업 화면, 도입 고객, 코치의 운영상 이점, 업종별 활용, 장비 FAQ 순으로 제품을 설명한다. 클라우드보드도 추상적인 기능 목록보다 실제 제어 기기와 TV의 모습을 먼저 보여준다. 고객 로고·후기는 동의를 얻은 실제 파일럿 자료만 사용한다. [CloudFit 홈페이지](https://cloudfit.tv/kr/)

확인한 한국 요금 페이지에서 CloudFit은 Free의 연결 화면 1대, Business의 매장당 월 199,000원·최대 15대·30일 체험을 안내한다. 다지점은 상담형이다. 여기서 참고할 것은 화면 수 중심의 비교와 명확한 도입 경로다. 가격이나 모든 기능을 그대로 모방하지 않는다. [CloudFit 요금제](https://cloudfit.tv/kr/pricing/)

CloudFit에는 영구 무료 1화면 상품도 있으므로 저렴하다는 설명만으로는 부족하다. 클라우드보드의 편집 경험, 한국어 안내, 설치 난이도, 매장 수업에서의 안정성이 실제 구매 이유인지 파일럿으로 확인해야 한다.

## 3. 가격 초안 — 수요·원가 검증 전 가설

아래 금액은 경쟁사 가격에서 산출한 적정가가 아니라 테스트할 제안이다. 모두 부가세 포함 표시를 제안하며 결제 화면에서도 같은 기준을 사용한다.

| 구분 | 제안 가격 | 제공 범위 | 사이트 버튼 |
|---|---:|---|---|
| 무료 체험 | 14일 0원 | Pro와 같은 기능, 등록 디스플레이 최대 3대, 카드 불필요 | 14일 무료로 사용하기 |
| CloudBoard Pro | 월 39,000원 / 매장 | 단일 운영 계정, 등록 디스플레이 최대 3대, 현재 수업·편집·대기 화면 기능 | Pro 구독하기 |
| 화면 확장·여러 매장 | 개별 상담 | 요구 화면 수와 운영 방식 확인 후 제공 가능 여부 안내 | 도입 문의 |

### 과금 단위

- 초기에는 1개 운영 계정이 관리하는 1개 매장을 계약 단위로 본다. 조직/매장 객체를 갖춘 다지점 관리 기능이 이미 존재한다는 뜻은 아니다.
- 3대는 등록된 디스플레이 수다. 휴대폰·태블릿을 컨트롤러로만 사용하면 디스플레이 수에 포함하지 않는다.
- 컨트롤러 1개 계정에서 같은 수업을 여러 화면으로 전달하는 범위다. 서로 다른 수업을 3개 공간에서 동시에 진행하는 상품으로 설명하지 않는다.
- 기기 교체 시 기존 기기를 해제해 한도를 돌려받는 동작을 제공한다. 한도는 서버에서 검사한다.
- 수업 실행 횟수·타이머 모양·브랜드 색상 같은 핵심 기능을 잘게 쪼개 과금하지 않는다.
- 저장 워크아웃/이미지 용량의 무제한 제공은 아직 약속하지 않는다. 실제 업로드 크기·전송량·보관 비용을 측정한 뒤 수량/용량 한도와 초과 동작을 공개한다.
- 4대 이상은 자동 결제 옵션으로 먼저 만들지 않는다. 파일럿의 요구와 동기화 성능을 검증한 뒤 확장한다.

### 파일럿과 정식 체험의 구분

- 기존 파일럿 고객을 자동 유료 전환하지 않는다. 기존 이용 종료일·혜택을 개별 안내하고 동의를 받는다.
- 정식 14일 체험은 첫 디스플레이 연결 후 사용자가 '체험 시작'을 확인할 때 시작하는 안을 추천한다. 가입만 하고 설치하지 못한 시간에 체험이 소진되지 않게 한다.
- 얼리 파트너 혜택을 운영한다면 '첫 6회 월 결제 29,000원, 이후 월 39,000원'처럼 횟수와 종료 후 금액을 명확히 한다. 평생 할인은 약속하지 않는다.
- 첫 출시는 월 결제만 제공한다. 연 결제는 유지율·환불 운영을 확인한 후 검토한다. 예시 연 390,000원은 연간 선결제 금액이며 출시 확정가가 아니다.

초기에는 별도 기능 소개 페이지를 늘리기보다 홈에 설명을 모으고 아래 경로를 갖춘다. 도메인은 미정이며 기존 CLYR 안내 페이지와 앱 계정을 연결한다.

### 홈의 권장 순서

1. **첫 화면:** '수업 진행은 화면에, 코치는 회원에게.' 실제 앱과 TV가 함께 나오는 이미지/짧은 영상. 기본 버튼 '14일 무료로 사용하기', 보조 버튼 '수업 화면 보기'.
2. **운영 장면:** 운동 순서·시간을 보여주고 수업 흐름을 조작하는 모습. 준비 시간 단축 수치 등 측정하지 않은 효과는 쓰지 않는다.
3. **시작 3단계:** 앱 로그인 → 디스플레이 연결 → 워크아웃 실행.
4. **기능 4묶음:** 만들기 / 화면 연결 / 수업 진행 / 우리 매장에 맞추기. 각 묶음에 실제 스크린샷 1개.
5. **파일럿 사례:** 매장 환경, 사용한 화면 수, 검증 기간, 허락받은 코치 의견. 확보 전에는 이 영역을 숨긴다.
6. **요금 요약:** 월 39,000원 제안과 체험 조건을 짧게 제시.
7. **FAQ와 마무리 버튼:** 장비·설치·취소·데이터·지원 안내.

시각 방향은 앱의 흰색/연보라 바탕, 보라색 강조, Pretendard를 이어간다. 앱 내부 편집 화면을 크게 보여주되 웹의 제목·간격은 반응형으로 구성한다. CloudFit의 이미지·후기·브랜드 자산은 복제하지 않는다.

### 요금 페이지 FAQ

- TV만 있으면 되는가? 호환 실행 기기와 네트워크 요건을 실제 검증 목록으로 설명.
- 한 계정에서 몇 대까지 연결되는가? 등록 화면 기준, 교체·해제 절차 설명.
- 각 화면에서 다른 수업을 진행할 수 있는가? 현재 지원 범위를 명확히 표시.
- 체험에 카드가 필요한가? 아니며 자동 결제되지 않는다는 제안.
- 해지하면 언제까지 쓸 수 있는가? 결제 기간 종료까지의 접근과 데이터 보관 구분.
- 설치를 도와주는가? 원격 안내의 실제 지원 범위와 연락 방법. 방문 설치 무료를 약속하지 않음.
- 앱 구독과 계정 삭제는 같은가? 별도 절차이며 계정 삭제 시 추가 결제가 남지 않도록 처리.

## 6. 체험·구독 흐름

홈/가격 → 기존 앱과 같은 계정으로 로그인 → 디스플레이 연결 안내 → 체험 시작 확인 → 14일 체험 → 사용자가 Pro 선택 → 결제 조건 확인/동의 → 서버 결제 확인 → 앱·웹에 권한 반영.

결제 성공 페이지로 돌아왔다는 사실만으로 유료 권한을 주지 않는다. 결제 사업자의 서버 응답/웹훅 검증을 거쳐 반영하며, 늦어질 때 '결제 확인 중' 상태를 표시한다. 취소·실패·중복 클릭·웹훅 재전송에도 중복 청구나 중복 연장이 없어야 한다.

제안하는 운영 원칙:

- 체험 종료 시 새 원격 수업 시작은 제한하고, 기존 콘텐츠는 읽기·미리보기 가능하게 한다. 즉시 데이터를 삭제하지 않는다.
- 체험/구독 만료나 결제 실패가 진행 중인 수업을 갑자기 멈추게 하지 않는다. 이미 실행한 수업은 종료까지 유지하고 다음 시작 시 권한을 확인한다.
- 해지 신청은 다음 갱신 중단으로 처리하고, 현재 결제 기간의 종료일을 표시한다. 기간 종료 전에는 '이용 종료'로 표시하지 않는다.
- 재결제 실패에는 안내와 재시도를 제공한다. 유예 기간은 운영자가 확정해 공개한다.
- 저장 데이터 보관 기간, 삭제, 환불과 중도 해지 정산은 기존 공개 정책·실제 처리 가능 범위와 맞춰 확정한다. 이 문서는 법정 권리나 환불 제한을 새로 정하지 않는다.
- 계정 삭제는 구독 해지와 연동하고, 추가 청구 중단·결제 기록의 별도 보관 요건을 처리할 수 있어야 한다.

## 7. 현재 코드와 유료화 전 필요한 작업

현재 `UserProfile`에는 `subscriptionPlan`, `subscriptionStatus`, `pilotEndsAt`, `displayLimit`이 있다. 신규 사용자 기본값은 파일럿/무료/디스플레이 3대다. 등록 한도를 확인하는 클라이언트 로직도 있다. 이것은 완성된 유료 구독 시스템이 아니다.

특히 현재 Firestore 규칙은 본인 `users/{uid}` 문서의 create/update에 구독 필드별 쓰기 제한을 두지 않는다. 이 필드를 그대로 결제 권한의 근거로 삼으면 사용자가 이용 등급·한도를 변경할 수 있는 구조다. 결제를 받기 전에 권한 데이터의 서버 전용 쓰기를 분리해야 한다.

필수 구현:

1. 결제 고객·정기결제 식별자를 Firebase UID 및 계약 매장과 연결.
2. 구독 상태와 실제 이용 가능 기간을 분리: 체험 중 / 정상 / 갱신 해지 예약 / 결제 실패 / 만료. 현재 canceled 라벨도 재검토.
3. 검증된 서버 작업만 플랜·한도·만료일 수정 가능하게 권한 규칙 변경. 기존 사용자·파일럿 이전 절차 포함.
4. 디스플레이 등록 및 새 수업 시작의 서버 권한 검사. UI 버튼 비활성화만으로 처리하지 않음.
5. 결제 웹훅의 서명 검증·중복 처리 방지·순서 역전·이벤트 누락 복구.
6. 취소/환불/재결제/계정 삭제와 권한 갱신 연결.
7. 결제수단은 PG의 호스팅 화면/토큰화를 사용하고 카드 원문을 앱 서버에 저장하지 않음.
8. 운영자가 구독·결제 상태를 조회하고 예외를 처리할 최소 관리 수단.

PG는 한국 원화 정기결제, 가입 자격, 심사·계약, 수수료, 자동결제/환불 API를 실제 확인한 뒤 선택한다. 특정 PG의 가입 가능 여부나 수수료를 이 초안에서 가정하지 않는다.

### 앱 스토어 결제 경로

웹 구독 판매와 앱 내 웹 결제 유도는 별개다. 웹에서 구매한 권한을 앱에서 이용하는 방향을 검토하되, 클라우드보드가 Apple의 기업용 서비스 또는 유료 웹 도구의 동반 앱 조건을 충족하는지는 판매 대상·웹 기능과 함께 확인해야 한다. B2B라는 이름만으로 예외 적용을 확정하지 않는다. 앱 내 결제 버튼/링크는 국가·플랫폼별 허용 조건을 확인한 뒤 설계한다. [Apple 3.1.3](https://developer.apple.com/app-store/review/guidelines/#other-purchase-methods)

Google Play는 앱에서 구매하지 않고 다른 곳에서 구매한 권한을 이용하는 소비 전용 앱을 허용하지만, 앱 안에서 외부 구매로 연결하는 흐름에는 별도 제한이 있다. 단순히 웹 결제 사이트를 만들었다고 앱에 그 링크를 자유롭게 넣을 수 있는 것은 아니다. [Google Play 결제 정책 FAQ](https://support.google.com/googleplay/android-developer/answer/10281818?hl=ko)

## 8. 단계별 출시

### A. 파일럿 모집 사이트

홈·요금 초안·설치 가이드·신청/문의·기존 정책 연결. 실제 결제 전에는 '체험 신청' 버튼을 사용하고 자동으로 유료 서비스가 시작된다고 보이게 하지 않는다. 실제 매장 사진과 수업 영상을 확보한다.

### B. 유료 판매 준비

가격/지원/저장 한도/체험 시작점/정책 확정 → 결제 사업자 계약 → 웹·앱 공통 계정 → 서버 구독 권한 → 구독 관리 → 결제·취소·실패·만료 검증 → 정식 결제 공개.

### C. 반복 구매 확인 후 확장

연 결제, 추가 화면 셀프 결제, 팀 초대, 조직 워크스페이스, 다지점 관리 순서로 수요에 따라 확장한다. 아직 제공하지 않는 기능이 포함된 요금제를 먼저 판매하지 않는다.
