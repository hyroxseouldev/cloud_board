## ③ 타이머 편집 화면에서 저장 완료 + 완료 버튼 하나로 통일

**현재 불편:** 블록 내부 `완료`와 상단 `편집 완료`가 겹치고, 이후 슬라이드 화면에서 다시 저장해야 실제 수정이 반영됩니다.

**제안 UX:** 블록의 시간·세트 변경은 화면 내 편집 상태에 즉시 반영하고, 상단 `저장` 버튼 하나로 실제 저장을 완료합니다. 저장 후 현재 타이머 화면에 머물며 결과를 안내합니다.

- [x] 블록 내부 완료 버튼을 제거하고, 피커에서 마지막으로 선택한 값까지 저장 대상에 포함합니다.
- [x] 상단 완료 액션을 단일 `저장` 액션으로 정리합니다.
- [x] 슬라이드 화면에서 추가 저장하지 않아도 해당 타이머 변경을 영구 저장합니다.
- [x] 저장 중 중복 요청을 막고, 성공·실패 상태를 정확하게 표시합니다.
- [x] 저장 성공 후 부모 슬라이드 편집 상태와 저장 기준값도 동기화합니다.
- [x] 타이머 외 제목·배경·색상 등 아직 저장하지 않은 편집값을 의도치 않게 저장하거나 덮어쓰지 않도록 저장 범위를 설계합니다.
- [x] 신규 워크아웃·미저장 슬라이드는 저장 대상 ID와 최초 생성 흐름을 확인합니다. 실제 저장 없이 성공 안내만 띄우지 않습니다.
- [x] 실행 취소·다시 실행을 유지하고, 저장하지 않은 변경이 있는 상태에서 뒤로갈 때 확인 흐름을 제공합니다.

**완료 기준:** 타이머 수정 → 상단 저장 → 편집 화면을 나갔다 재진입해도 수정값이 유지됩니다. 별도의 슬라이드 저장이 필요하지 않고 다른 편집 내용도 유실되지 않습니다.

**구분:** 이 항목은 편집 데이터 저장 개선입니다. 진행 중인 수업의 타이머를 즉시 바꾸는 기능을 추가하는 것으로 해석하지 않습니다.

### 변경과 검증 근거

1. 자동 배포: `google-play-main.yml`의 `track: internal`을 기존 `alpha`로 수정. `status: completed`, `changesNotSentForReview: false`로 업로드/심사 요청. 빌드 번호는 기존 `GITHUB_RUN_NUMBER + 2` 유지. 테스터·국가·참여 링크를 바꾸는 요청은 없음.
2. Display → Control: 모드 저장 성공 뒤 `/displays`로 `go`, 중복 스택 없이 등록 목록 유지. 390px·834px 위젯 테스트 통과.
3. 타이머: 피커 즉시 반영, 상단 저장 하나, 성공 후 머무름. 저장된 워크아웃의 해당 모듈 시간·휴식·세트·블록만 병합. 부모/슬라이드의 미저장 제목·본문·옵션 유지. 신규 수업은 이름을 받아 실제 저장하며, 실패·중복 요청·뒤로가기 취소/버리기·재진입을 검증.
4. 시작: 새 수업은 브리핑 없이 설정된 카운트다운(0~60초)으로 시작. 기존 세션의 브리핑 데이터 호환과 별도 브리핑 미리보기는 유지. 이미지 사전 준비와 효과음 경로 유지.
5. 종료: 완료 전용 화면과 대기를 제거. 제어 화면은 시작한 경로로 복귀, TV는 대기로 전환. 확인창·알림 정리 유지. 중복 종료 요청 병합, 서버에서 사라진 세션의 로컬 캐시 제거. 자연/수동/원격 세션 제거 복귀를 검증.
6. 세트: 공통 `WorkoutSlideCanvas`에서 타이머와 동일 앵커/크기 사용, 바로 아래 중앙 정렬. 타이머 숨김 시 세트 독립 표시 유지. 가장자리/화면 맞춤 안전 여백/브랜드 하단 영역을 위젯 좌표로 검증. 사용자가 임의로 옮긴 타이머와 본문 간 배치는 실기에서 추가 확인.
7. 새로고침 분석: 기존 버튼은 세션·디스플레이·브랜드·예약·연결 구독을 재조회했으며 새 데이터를 쓰지 않았음. 기존 실시간 구독에 연결 복구/앱 resumed 시 재구독, 오류 구독의 15초 재시도 추가. 등록된 TV의 새로고침 버튼 제거. 미등록 기기의 연결 코드 재발급은 유지. 재연결·앱 복귀 후 브랜드 재조회 테스트 통과.
8. OFF: `black` 대신 `standby` 전송, ON은 기존 `auto`. 수업 송출만 제외하며 등록/계정 유지. 명시적 standby는 예약 블랙 화면보다 우선. 현재 수업 및 종료된 세션에 대한 OFF/ON 테스트 통과. 기존 명시적 black 명령은 계속 지원.
9. 삭제: ID별 추적, 대상 스피너, 중복 조작 차단, 성공 뒤 250ms 페이드/높이 축소. 목록이 서버 응답보다 빠르거나 느려도 성공 전 제거하지 않고 성공 후 다시 나타나지 않게 처리. 실패 시 유지·오류 안내, 이름 포함 성공 안내, 모션 감소 대응. 서버 목록 순서 변경 시 기존 타일 순서를 안정적으로 유지.
