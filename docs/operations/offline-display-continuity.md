# STA-195: 준비된 수업의 일시 단절 처리

프로세스가 살아 있고 이미 준비한 동일 수업은 연결이 끊겨도 로컬 시계로 운동·휴식·슬라이드를 진행한다. 일시정지, 설명 대기, For Time의 제한시간 도달은 자동으로 다음 구간을 시작하지 않는다. 실제 계정 변경, 권한 거부, 연결 해제, 서버에서 확인한 삭제·종료는 계속 우선한다. 앱 강제 종료 후 자동 재생이나 새 수업의 오프라인 시작을 제공하는 기능은 아니다.

수업 디스플레이에는 연결 단절 안내나 배지를 표시하지 않는다. 컨트롤러의 기존 연결 안내는 유지한다.

## 준비된 소리

웹은 준비 단계에서 번들 WAV 두 개(시작 비프·짧은 카운트다운)의 bytes를 읽어 동일 프로세스의 재생과 공유한다. 현재 합계 약 128KiB이며 각 파일 1MiB 상한과 10초 로드 제한을 둔다. 브라우저 HTTP 캐시와 관계없이 준비 후에는 `BytesSource(audio/wav)`로 재생하므로 같은 음원 URL을 다시 요청하지 않는다. 다운로드·형식 검사·오디오 소스 준비가 실패하면 `audioReady`를 성공으로 기록하지 않으며 다음 준비에서 재시도한다.

계정별 데이터가 아닌 고정된 공개 번들 두 개만 프로세스 수명 동안 유지한다. 네이티브는 기존 `AssetSource`와 로컬 AudioCache 경로를 유지하고, 합성 음원과 중복 비프 방지 조건은 바꾸지 않는다. 준비된 bytes와 별개로 브라우저의 자동재생 허용·음소거·출력 장치 상태는 기존 제약을 따른다.

## 이미지와 종료 수명

- 준비 단계에서 원격 이미지의 압축 bytes를 현재 수업용으로 보관한다. 준비 ID와 실제 재생 ID는 다르므로 같은 계정 범위에서 이미지 URL 목록이 일치할 때만 준비 자료를 재생으로 넘긴다.
- 한 수업의 보관 상한은 64MiB, 개별 다운로드는 16MiB이다. 전송 중에도 크기를 검사한다. 기존 Flutter 디코딩 캐시는 별도로 기존 상한을 유지한다.
- CORS 때문에 bytes를 가져올 수 없는 URL은 기존 HTML 이미지 경로를 유지한다. 이 경우 live image listener를 보관하고 실제 가로×세로×4 바이트를 같은 64MiB 예산에 계산한다.
- 상한을 넘거나 준비하지 못한 개별 이미지의 오프라인 표시는 best effort이다. 활성 수업은 해당 이미지 오류를 건너뛰고 뒤 이미지 준비와 타이머를 계속 진행한다. 기존 시작 전 준비 확인은 엄격하게 유지한다.
- 수업 종료·자료 교체·계정 변경·확인된 연결 해제에 보관 자료를 해제한다. 시작하지 않은 준비 자료는 요청의 만료 시각에 해제한다. 화면만 다시 만들어졌을 때는 동일 수업 자료를 유지한다.
- 디스플레이가 마지막 자동 구간에 도달하면 owner/session 단위 완료 표식을 메모리에 유지한다(최근 16개). 같은 세션의 오래된 `playing` 결과가 돌아와도 재생을 다시 시작하지 않는다. 공유 `activeSession`을 디스플레이가 완료 상태로 쓰지는 않는다. 새 세션 ID는 정상적으로 시작한다.

## 실제 기록 경로

기존 `users/<ownerId>/operations/events/<eventId>`에만 기록한다.

| 유형 | 단계 | 의미 |
| --- | --- | --- |
| `connection_failed` | `display_connection` | 준비된 수업 중 서버 접속 단절을 관찰함. 재생 중단을 의미하지 않음 |
| `connection_recovered` | `display_connection` | 접속과 최신 상태 확인 후 같은 incident의 복구를 관찰함 |
| `display_playback_completed` | `local_completion` | 이 디스플레이의 마지막 자동 구간이 끝남 |

`connected`는 발생 당시 접속 여부이며 `occurredAtMs`는 기존 서버 시각 보정을 적용한 발생 시각이다. 단절·복구는 같은 incident ID로 연결하고 로컬 완료는 한 세션에서 한 번 기록한다. 이 기록은 가짜 ERROR로 전송하지 않으며 `playback_completed` 수업 집계나 기존 모니터링 웹훅에 포함하지 않는다. 기존 paired display·소유자·기기·취소 권한 조건을 유지하면서 새 로컬 완료 유형만 RTDB 규칙에서 추가 허용한다.

기존 `DiagnosticQueue`를 재사용한 operations 전용 outbox의 로컬 키는 `cloudboard.operations.v1.<projectId>.<FirebaseAppName>`이다. owner/인증 UID/익명 여부/device ID가 바뀌면 이전 범위의 큐를 비운다. 최대 30개, 24시간 TTL이며 동일 event ID와 원래 발생 시각으로 재전송한다. 이 큐는 재생 명령을 재전송하지 않는다. 서버 규칙을 먼저 반영하지 않은 환경에서는 새 로컬 완료 유형이 거부될 수 있으며, 재생은 그 실패에 영향을 받지 않는다.

## 실제 브라우저 검증

개발 또는 demo emulator의 기존 Display 탭을 사용한다. 최소 3개 원격 PNG의 준비 완료와 시작 ACK를 확인한 뒤 해당 브라우저 컨텍스트만 offline으로 전환한다. 기존 RTDB WebSocket의 종료와 이후 HTTP 실패를 확인하고 페이지는 foreground로 유지한다. SDK `goOffline()`만 호출한 결과로 전체 네트워크 차단을 검증했다고 기록하지 않는다.

남은 수업보다 오래 차단하여 구간·슬라이드·로컬 종료를 확인한 뒤 같은 탭을 복구한다. 오래된 수업이 다시 재생되지 않는지, 큐의 원래 발생 시각과 같은 event ID가 실제 RTDB에 저장되는지, 새 수업이 시작되는지 확인한다. paused/For Time 사례는 별도로 확인한다. mock 위젯 테스트 통과와 실제 브라우저/SDK 검증 결과를 구분해서 인계한다.
