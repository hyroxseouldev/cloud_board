# CloudBoard 매장 파일럿 운영서

## 파일럿 범위

- 매장 1곳, 코치 2~3명
- 컨트롤러 1대, 디스플레이 1~2대
- 실제 60분 수업 10회
- 한 컨트롤러에서 동시에 한 개 수업 운영

## 수업 전 1분 점검

1. 디스플레이의 기기명과 구역명이 맞는지 확인한다.
2. 컨트롤러에서 온라인 표시를 확인한다.
3. 워크아웃의 재생 버튼을 누르고 이미지 준비 결과를 확인한다.
4. 소리 테스트를 실행한다.
5. 총 슬라이드 수와 수업 시간을 확인한 뒤 3초 카운트다운을 시작한다.

## 수업 중 장애 대응

- `오프라인 · 로컬 재생`: 수업은 그대로 진행하고 네트워크를 확인한다.
- 이미지 준비 실패: 수업 시작을 취소하고 해당 슬라이드 이미지를 다시 등록한다.
- 디스플레이 미반영: 기기 목록에서 온라인과 `명령 확인 #revision`을 확인한다.
- 앱 종료: 앱을 다시 실행하면 저장된 세션으로 복귀한다.
- 잘못 종료: 종료 확인창에서 `계속 진행`을 선택한다.

## 장애 테스트

파일럿 전 다음 항목을 각각 한 번 실행한다.

1. 재생 중 Wi-Fi를 30초 끈 뒤 타이머가 계속되는지 확인한다.
2. Wi-Fi 복구 후 5초 안에 동기화 표시가 돌아오는지 확인한다.
3. 재생 중 컨트롤러 앱을 종료하고 다시 실행해 세션이 10초 안에 복원되는지 확인한다.
4. 디스플레이 앱도 같은 방법으로 복원되는지 확인한다.
5. 컨트롤러 1대와 디스플레이 2대에서 다음·이전·일시정지 명령을 반복한다.
6. 마지막 슬라이드가 자동으로 닫히지 않는지 확인한다.

## 통과 기준

- 10회 수업 동안 치명적인 타이머 또는 슬라이드 오류 0건
- 30초 네트워크 단절 중 재생 유지, 복구 후 5초 안에 재동기화
- 앱 재실행 후 10초 안에 진행 중 수업 복원
- 명령 후 2초 안에 디스플레이의 revision 확인
- 깨진 이미지, 화면 자동 꺼짐, 자동 수업 종료 0건
- 코치 3명 중 2명이 두 번째 수업부터 도움 없이 운영

## 배포와 롤백

- `develop`에서 테스트 후 `main`에 병합한다.
- CI의 포맷, 분석, 테스트, 웹 빌드가 모두 통과해야 배포한다.
- 문제가 발생하면 직전 정상 커밋을 `main`에 다시 배포한다.
- 치명적인 장애가 한 번이라도 발생하면 다음 실제 수업 전에 원인과 재현 테스트를 추가한다.
