# CloudBoard 1.3.5 개발 후보

2026-10-20 사용자 요청에 따른 develop 야간 테스트 기준이다. 앱 표시 버전은
`1.3.5`이며 pubspec의 빌드 번호 `5`는 스토어 업로드 번호가 아니다. 플랫폼별
실제 업로드 번호는 기존 배포 절차에서 별도로 정한다.

## 포함 범위

- STA-189 1차 A/B/C: 수업 저장 준비 병렬화, 수정 시 불필요한 usage 집계 생략,
  센터 템플릿 PNG 재사용, 이미지·오디오 병렬 준비. PR #118, #119.
- STA-197: 상태 신호 60초/무응답 판단 180초의 기본 정책, Remote Config 관리,
  수업 중 정책 유지 및 이전 연결의 늦은 쓰기 방지. PR #118.
- STA-195: 준비 자료 유지, 자동 수업의 로컬 종료 유지, 단절·복구·로컬 종료
  기록과 영속 재전송, 수업을 가리는 연결 표시 제거, 웹 준비 음원 재사용. PR #120.
- 이미 develop에 반영된 센터 템플릿·편집 화면·미리보기 개선, 재연결 때 지난
  음원 중복 재생 방지, 수업 종료 수신 실패 오탐 수정도 함께 검증한다.

STA-189 2차/3차는 각각 STA-198/STA-199 Backlog이며 이 후보에서 새로 구현하지
않았다. `release-notes/current.json`은 후보 문구이다. 실제 배포·업로드 증거를
확인하기 전에는 앱의 공개 업데이트 소식으로 발행하지 않는다. 정식 출시 때
플랫폼별 직전 실제 배포 SHA와 후보 main SHA를 다시 비교한다.

## 적용 상태

- develop 코드 통합과 개발 후보 버전 확정만 수행한다.
- 서버 최소 지원 버전·필수 업데이트는 변경하지 않는다. 사용자가
  “필수 설정은 아니다”라고 정정했으므로 활성화 여부는 미결정이다.
- main 승격, 릴리스 태그, 개발/운영 배포, 스토어 업로드·공개는 수행하지 않는다.
- STA-189의 `saveWorkout`, `syncWorkoutPlanUsage` 최적화는 서버 코드 배포가
  필요하다. 배포 전 개발 서버에서 새 앱을 실행해도 해당 서버 최적화가 적용된
  것으로 간주하지 않는다.
- STA-195의 `display_playback_completed` 저장은 후보 RTDB 규칙 배포가 필요하다.
  규칙 미반영 시 기록이 거부될 수 있지만 로컬 재생을 차단하지 않는다.
  새 함수·모니터링 서비스를 만들지 않았고 이 로컬 완료 이벤트는 기존
  수업 종료 웹훅과 집계에서 제외된다.

## 검증과 자정 인계

기능 PR 본문에 실제 검증 SHA·명령·결과를 기록한다. PR의 인계 확인 체크를
실제 앱 테스트나 전체 CI 통과로 간주하지 않는다.

- PR #119: 관련 Flutter 68개, Node 11개, 분석, quota 계약 및 실제 Chrome
  Dart repository → Storage → callable → Firestore 서버 재조회.
- PR #118: 관련 Flutter 89개 및 마지막 변경 영향 범위 36개, 분석, RTDB 계약.
- PR #120: 기본 관련 Flutter 67개, 웹 음원·배지 보완 영향 범위 87개,
  정적 분석, RTDB 권한 계약 8유형, 기존 웹훅 제외 13개 통과. 최종 SHA
  `aa658fecd4c031c44314b5a8a1ae4205fd822f25`의 실제 Chrome에서는 시작
  1.623초 후 HTTP/WebSocket을 차단한 66초 수업이 3장 PNG·운동/휴식
  구간을 지나 66.044초에 로컬 종료했다. 단절 중 data WAV 30회가 실제
  media play/ended를 마쳤으며 음원 HTTP 실패·page error·수업 연결 배지는
  없었다. 재연결 뒤 오래된 playing이 재생을 되살리지 않았고 원래 이벤트
  ID·발생 시각으로 로그가 저장되고 큐가 비워졌다. 스피커 청취나 iOS
  컨트롤러 UI 검증으로 간주하지 않는다. 상세 증거는 PR 본문을 따른다.
- 후보 버전·업데이트 소식: `node --test tool/update-news/news.test.mjs` 6개
  통과. 이 후보 문서 추가는 런타임을 변경하지 않는다.

로컬 SDK 확인은 `demo-cloudboard-studio`와 합성 데이터로 수행한다. iOS
컨트롤러 UI·실제 개발 계정 수업이나 Android TV 실기기 검증을 대체하지 않는다.
이미지 보관은 한 수업 64MiB/장당 16MiB로 제한되며 한도 밖이나 준비 실패
이미지까지 오프라인 표시를 보장하지 않는다. 관련 한계는
[오프라인 디스플레이 동작](../operations/offline-display-continuity.md)에 있다.

22시에는 iOS 빌드하지 않는다. 자정 자동화는 기존 팀장 세션에서 실행 시점의
최종 origin/develop SHA를 고정하여 signed development iPad 앱과 같은 SHA의
8080 웹 Display를 준비한다. 기존 Google 로그인과 기기 연결을 보존하고,
개발 계정으로 6분 수업·일시정지/재개·종료 후 15초를 실제로 확인한다.
운영 서버나 실제 센터 수업에 장애를 주입하지 않는다.

최종 SHA와 로컬 증거·남은 검증은 팀장 작업 공간
`output/nightly/2026-10-20.md` 및 자정 실행의
`output/daily-class-test/YYYY-MM-DD/report.md`로 인계한다.
