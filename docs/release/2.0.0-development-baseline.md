# CloudBoard 2.0.0 개발 기준점

2026-10-21 사용자 요청에 따라 추가 테스트를 중단하고 완료된 개발 코드를
`feature/2.0.0-baseline`에 모아 보존한다. 앱 표시 버전은 `2.0.0`, pubspec의
기존 개발 빌드 번호는 `5`다. 이 번호는 실제 스토어 업로드 번호가 아니다.
이 문서를 추가한 커밋이 2.0.0 개발 기준 커밋이다. 이후 21:10 KST 사용자
추가 지시로 main 승격과 수동 운영 배포 준비를 승인받았다. 배포는
21:20 KST 이후 모바일 → 서버 → 웹 순서가 요청되었으며 실제 단계별 결과는
별도 배포 영수증으로 확인한다.

## 검증·적용 상태

- 사용자 지시에 따라 이 기준점에서 추가 테스트·E2E·앱 빌드를 실행하지 않았다.
- 이전 검증은 각 PR의 실제 명령·대상 SHA·결과를 따른다. STA-207 관련
  오프라인 테스트 16개 통과를 전체 통합 E2E 통과로 간주하지 않는다.
- 실제 저장·재조회·수업 테스트와 구버전/신버전 혼합 검증은 미완료다.
- 기준점 준비 시 위 PR은 원격 develop에 미병합 상태였다. 이후 기능 PR을
  develop에 squash하고 2.0.0 버전/소식을 반영한 뒤 main으로 통합 승격한다.
  기준 커밋 자체는 실제 배포 완료나 미실행 검사의 통과를 의미하지 않는다.
- 사용자가 확인 중인 iPad 앱은 기존 1.3.5(5) 설치본과 실행 중 Dart
  `323afbad835b94b05d97d4fa441f241146c2635d`를 유지한다. 2.0.0으로
  새로 빌드·설치하거나 재시작하지 않았다.
- 새 사용자 지시의 main 승격·수동 배포는 별도 실행으로 기록한다. 추가
  테스트 중단은 유지하고 수동 CI 생략 사유를 남긴다. 기존 배포 도구의
  서버 호환성·고정 SHA·서명·환경 조건은 통과 여부를 확인하며 우회하지 않는다.
- 업데이트 소식은 직전 운영 1.3.2 소스
  `83751b1c80c26312e19f2866fbeeb700bb905e73` 이후의 사용자 변경을 기준으로
  `release-notes/current.json`에 준비했다. 플랫폼별 실제 배포 기준은
  배포 담당이 영수증과 다시 대조한다. 업로드·심사·공개는 각각 구분한다.
- 기존 클라이언트의 API·필드·권한·수업 명령 계약과
  [호환성 원칙](../released-client-compatibility.md)을 유지한다.
