# CloudBoard 센터별 AI 디자인과 수업 이미지 자동 제작 계획

작성일: 2026년 10월 9일 · 상태: 로컬 기능 브랜치 구현·검증 · 브랜치: `feat/ai-slide-design-studio` · 기반: main `e3f39e6`

**디자이너가 없는 센터도 자기 디자인으로 수업 이미지를 만들고, 매일 운동 내용만 바꿔 반복 제작할 수 있게 한다.** 처음에는 기본 디자인, AI의 새 디자인 제안, 원하는 템플릿 가져오기 중 하나로 시작한다. 선택한 디자인을 센터·클래스에 저장한 뒤에는 운동 메모만 넣으면 글자 크기·줄바꿈·간격·정렬이 자동으로 맞춰져야 한다.

사용자가 줄이고 싶은 일은 매일·매주 운동 내용을 바꿔 이미지를 다시 만드는 반복 작업이다. STATION D의 WOD 6장과 돌파 클래스 1장은 한 고객의 목표 사례다. 다른 센터에는 그 센터의 개성과 필요에 맞는 디자인을 제공한다.

## 이번 브랜치에서 구현한 범위

- 기본 디자인 4종을 AI 호출 없이 선택하고 편집할 수 있다. 짧은 목록은 글자 크기와 행간을 함께 늘려 화면을 채우며, 카드는 동일 높이 격자로 배치한다.
- 스타일 설명으로 정보 배치가 다른 AI 디자인 3안을 받아 같은 내용으로 비교한다.
- 참고 이미지 한 장을 분석해 색상·서체 계열·배치·장식 문자를 편집 가능한 스타일로 가져온다. 원본 폰트·로고·서예 이미지를 정확히 복제하는 기능은 아니며, 표현하지 못한 특징은 화면에 알린다.
- 돌파는 스타일 추정과 별도로 원본 PNG를 사용하는 고정 템플릿으로 제공한다. 원본 한자·배경·Brick Session 제목·변경하지 않은 글자는 그대로 보존하며 시간·운동 4행만 교체한다. 제목은 서예 위에 합쳐진 원본의 일부이므로 고정한다. 원본 폰트가 알려지지 않아 변경한 문구는 번들 명조 서체로 렌더링한다. 고객 참고 템플릿은 개발 빌드의 별도 선택 영역에만 노출하며 공통 기본 4종에 포함하지 않는다.
- UNBROKEN·STRENGTH·MAX·SWEAT·HYROX도 원본 PNG로 등록한다. HYROX 싱글/팀을 구분한 총 6장과 돌파를 `센터 원본 템플릿`에서 선택한다. 상단 띠·분류·번호·변경하지 않은 글자는 원본 픽셀을 유지하고, 수정한 제목·시간·운동 영역만 교체한다. 운동은 원본별 4~6행까지 지원하며 빈 행의 번호도 제거한다. 원본 서체는 미제공이므로 바꾼 글자는 번들 서체로 영역 안에 맞춘다.
- 진입 버튼과 페이지 이름을 `수업 이미지 생성`으로 통일하고, 보라·분홍 그라데이션의 소문자 `beta` 배지를 사용한다. 바텀 시트를 전체 페이지로 전환해 뒤로 가기·초안 복원·슬라이드 추가와 작은 화면의 키보드 입력을 유지한다.
- `beta`는 제목 바로 옆에 배치하고, 슬라이드 추가는 상단 `+` 아이콘 액션으로 제공한다. 하단 네비게이션은 `내용 / 템플릿 / 수업 메모 / 디자인 만들기`로 나눈다. 템플릿에는 기존 카탈로그·센터 원본·저장한 디자인을 두고, 새 디자인 도구는 별도 화면의 `스타일 제안 / 이미지로 시작`에서 제공한다. 탭을 오가도 수업 내용과 디자인 설명·참고 이미지 선택을 유지한다.
- 템플릿 화면에 직접 선택·수정은 AI 토큰과 생성 횟수를 사용하지 않는다고 안내한다. 탭 진입과 문구 입력만으로는 생성 요청을 보내지 않으며, 기존 생성 버튼을 눌렀을 때만 요청한다.
- `수업 내용 정리하기`, `스타일 제안`, `이미지로 시작`처럼 작업 중심 문구를 사용한다. 기존 AI 내용 생성 기능은 `수업 메모`에서 계속 제공한다.
- 센터 식별자와 계정 권한을 확인해 클래스별 디자인을 여러 개 저장한다. 예전 계정의 템플릿과 최근 선택도 유지한다.
- 다음 수업에서는 선택한 디자인과 클래스명을 재사용하고 새 운동 메모로 내용을 생성한다. 이전 수업의 시간 안내는 자동 복사하지 않는다.
- 제목·본문·분류·시간 문구와 글씨·색상·장식은 계속 수정할 수 있다. 일반 슬라이드 편집·보관함·워크아웃 저장에도 스타일 스냅샷을 보존한다.
- 새 렌더러는 미리보기·재생·1920×1080 PNG에 같은 측정을 사용한다. 기존 렌더러는 유지하고 모르는 디자인 버전은 PNG로 표시한다.
- AI 색상은 HEX로 받아 서버에서 변환하고 본문·제목 대비를 검증한다. 기존 프리미엄 판정·AI 사용량·예산·캐시·실패 환급을 공유한다.

main에는 병합하지 않는다. 초기 자동 검증은 [로컬 미리보기 절차](../tool/studio-preview/README.md)의 Firebase 에뮬레이터를 사용했고, OpenAI는 사용자가 승인한 기존 키로 실제 호출했다. 사용자 피드백에 따라 최종 시뮬레이터는 운영 진입점으로 빌드해 기존 사용자 계정에서 검수한다. 운영 계정 로그인에는 규칙 변경이 필요하지 않으며, 사용자 지시에 따라 서버와 규칙은 배포하지 않는다. 새 디자인 추천 callable·여러 클래스 디자인의 원격 저장은 후속 배포가 필요하다. 기본 디자인·WOD/돌파 원본의 로컬 편집과 기존 내용 정리 기능은 현재 앱에서 확인한다.

아래 기획 중 로고/장식 이미지 자산 직접 배치, 자유로운 새 레이아웃 생성, 센터 운영 브랜드 자동 연결, 주간 일괄 제작, 실사용 시간 단축 측정은 후속 범위다. 이번 버전의 AI는 검증된 네 디자인 계열 안에서 새 조합을 만들며, 참고 이미지도 이 표현 범위로 해석한다.

## 제품의 두 가지 작업

| 작업 | 언제 하는가 | 사용자가 얻는 결과 |
| --- | --- | --- |
| 우리 센터 디자인 만들기 | 첫 시작 또는 디자인을 바꾸고 싶을 때 | 재사용할 센터·클래스 템플릿 |
| 오늘 수업 이미지 만들기 | 매일·매주 | 새 운동 내용이 들어간 완성 이미지와 편집 가능한 수업 슬라이드 |

두 작업을 연결하되, 매일 제작할 때 디자인을 다시 정하지 않게 한다. 새로운 스타일 제안은 사용자가 요청할 때 제공한다. 평소에는 저장된 스타일을 안정적으로 재사용한다.

## 센터가 시작하는 세 가지 방법

### 기본 디자인으로 바로 시작

센터명만으로도 첫 결과를 만들 수 있게 한다. 로고, 참고 이미지, 디자인 프롬프트는 필수로 요구하지 않는다. 로고나 대표색이 있으면 반영하고, 없으면 완성된 기본 스타일을 제공한다.

초기 기본 디자인은 다음 네 계열을 제안한다. 이름·수량은 출시 디자인 검수에서 확정한다.

| 계열 | 주로 어울리는 수업 | 표현 특징 |
| --- | --- | --- |
| 밝은 번호 보드 | 스테이션·순서가 있는 WOD | 밝은 배경, 헤더, 번호 배지, 큰 운동 목록 |
| 어두운 집중 보드 | 강도 높은 운동·타이머 중심 수업 | 높은 명암 대비, 큰 시간, 명확한 운동행 |
| 클래스 포스터 | 특정 클래스·이벤트·세션 | 강한 제목, 여백, 별도 장식 영역 |
| 섹션 카드 보드 | 웜업·근력·메인 등 여러 파트 | 파트별 묶음과 읽기 순서 |

공통 디자인에는 특정 고객의 이름·로고·서예 자산·운동 내용을 넣지 않는다. 기본 디자인을 선택한 뒤에도 센터색과 글씨 분위기를 간단히 바꿔 자기 템플릿으로 저장할 수 있다.

### AI에게 새로운 디자인 제안받기

센터의 대표색·로고가 있으면 재사용하고, 원하는 느낌을 짧게 선택하거나 입력한다. 예를 들어 ‘깔끔하게’, ‘강렬하게’, ‘밝고 친근하게’, ‘포스터처럼’으로 요청할 수 있다.

AI는 **동일한 수업 내용으로 서로 다른 디자인 3안**을 제안한다. 세 안은 색만 바꾸는 수준을 넘어 제목 계층, 정보 배치, 번호·섹션 표현, 여백과 글씨 분위기에 차이가 있어야 한다. 운동 내용과 수치는 세 안에서 동일하게 유지한다. 사용자는 하나를 선택하거나 특정 안을 바탕으로 다시 제안받고, 최종 디자인을 저장한다.

‘새로운 디자인’은 편집 가능한 결과로 제공한다. 제목과 운동 내용을 수정할 수 없는 한 장의 그림으로만 제공하지 않는다. 선택한 뒤에는 매일 생성할 때 디자인이 달라지지 않는다.

### 원하는 템플릿 가져오기

기존 수업 이미지나 선호하는 참고 이미지 한 장을 등록하고, 색·서체·배치·장식 중 유지하고 싶은 부분을 선택한다. AI가 디자인 특징을 읽어 편집 가능한 템플릿 초안을 만든다. 같은 내용이 들어간 미리보기로 원본과 비교한 뒤 저장한다.

정확한 서체나 독립된 로고·장식 자산이 없으면 반영 가능한 범위와 대안을 보여준다. 원하는 스타일을 반영하는 데 필요한 확인은 최초 등록 과정에서 마치고, 매일 제작할 때 다시 요구하지 않는다. 참고 이미지의 운동 내용은 매일 재사용할 템플릿에 섞어 저장하지 않는다.

이번 STATION D 번호 보드와 돌파 포스터는 이 경로를 검증할 첫 사례다.

## 매일 만드는 흐름

**클래스 선택 → 운동 메모 붙여넣기 → 자동 완성 → 필요한 부분만 수정 → PNG 저장 또는 수업에 사용**으로 끝난다.

1. 최근 사용한 클래스와 저장한 디자인을 기본으로 보여준다.
2. 평소 작성하던 제목·시간·운동 목록을 그대로 붙여 넣는다. 운동 한 줄마다 폼을 작성하거나 약어를 풀어쓰게 하지 않는다.
3. AI가 제목·분류·시간 문구·운동행을 정리하고, 렌더러가 저장된 클래스 디자인에 맞춰 배치한다.
4. 완성 이미지를 먼저 보여준다. 내용이 불명확하거나 가독성이 부족한 부분만 표시한다. 운동 한 행을 수정하면 필요한 배치만 다시 계산한다.
5. 이미지 저장 또는 현재 워크아웃 초안에 추가로 바로 연결한다. 실제 워크아웃 저장은 기존 단계를 유지한다.

예를 들어 ‘돌파’를 선택하고 아래 메모를 넣으면 저장한 검정·붉은색·흰색 포스터 스타일로 완성되어야 한다.

```text
Brick Session
6mins On / 90s Off
Ski 250m + Sled Pull 1 Way
Run 250m + FMCTP 30
Ski 250m + Wall Ball 30
DV Press 8 + BTP 10
```

다음날에는 운동 메모만 바꾼다. 이전 이미지의 문장을 지우고 글자 크기·줄바꿈·위치를 다시 맞추는 일을 줄이는 것이 핵심이다. 자주 반복되는 디자인 수정은 ‘이번 수업만’ 또는 ‘클래스 기본 디자인에도 반영’으로 구분한다. 클래스 기본값을 바꿔도 이미 저장한 과거 수업은 바뀌지 않는다.

## 센터와 클래스의 디자인 관계

| 구성 | 보관할 내용 | 재사용 범위 |
| --- | --- | --- |
| 공통 기본 디자인 | 검수한 레이아웃·서체 조합·색상 기본값 | 모든 센터가 시작할 수 있는 카탈로그 |
| 센터 브랜드 | 센터명, 로고, 대표색, 기본 디자인 | 해당 센터 |
| 센터 템플릿 | 기본 디자인·AI 제안·참고 이미지에서 선택한 디자인과 자산 | 해당 센터가 저장한 여러 디자인 |
| 클래스 스타일 | 센터 템플릿 선택, 클래스명, 강조색·배치 등 필요한 변형 | 돌파·HYROX 등 해당 클래스 |
| 수업 내용 | 날짜별 제목·시간 문구·운동행과 원문 연결 | 해당 수업 |

센터가 달라도 모두 같은 모습이 되지 않도록 여러 디자인 계열을 지원한다. 동시에 한 센터의 로고와 공통 분위기는 유지하면서 클래스별 개성을 줄 수 있게 한다. 기본 디자인에서 만든 템플릿, AI가 새로 제안한 템플릿, 기존 스타일을 가져온 템플릿은 저장·선택·수정·재사용 흐름이 같아야 한다.

STATION D의 7장은 해당 고객의 레퍼런스다. 이 고객의 자산을 자동으로 다른 센터의 기본 디자인에 넣거나, 다른 센터의 결과에 STATION D 명칭·분류를 채워 넣지 않는다.

## 현재 기능과 개선 범위

현재 AI는 텍스트 최대 6,000자에서 편집 가능한 한 장을 생성한다. 내용·디자인·원문 탭, 실행 취소, 초안 복원, 원문 수치 검증, PNG 출력 기반을 갖고 있다. 일반 편집기에는 슬라이드·스타일 라이브러리도 있다. 기존 기반을 연결·확장한다.

| 현재 코드에서 확인한 상태 | 개선할 내용 |
| --- | --- |
| AI 편집기의 센터 테마 한 개 | 센터별 복수 템플릿·클래스 스타일·최근 선택 기억 |
| 제목·본문 모두 Pretendard 공통 스타일 | 텍스트 역할별 서체·크기·굵기·색·정렬 |
| 번호/목록/인터벌과 자동/2열/카드 배치 | 여러 센터에 어울리는 디자인 계열, 헤더·분류·번호 배지·장식 영역 |
| 생성형 디자인과 이미지 표시가 분리됨 | 로고·서예 등 장식을 별도 레이어로 합성하고 운동 텍스트는 편집 가능하게 유지 |
| 텍스트 내용만 AI 생성 | 선택형 새 스타일 제안과 최초 참고 디자인 등록 |
| 서버의 원문 ID·일부 수치 검사 | 클라이언트 원문 연결, 운동명·순서·복합운동·스케일링 값 보존 |
| AI 미리보기에 워크아웃 브랜드 미전달 | 미리보기·PNG·실제 화면에서 센터 브랜드와 배치 일치 |

브랜드 체계를 처음부터 새로 만들 필요는 없다. 기존 온보딩에 `storeId`와 `centers/{storeId}`가 있고, 운영 브랜드에는 센터명·로고·대표색이 있다. 이 정보를 센터 디자인의 시작값으로 연결한다. 다만 현재 AI 테마와 다수의 저장 경로는 `uid/ownerUid` 중심이므로, 센터 ID 연결과 기존 테마 이관은 명시적으로 설계해야 한다.

## 생성과 편집의 품질 기준

- 운동명·수치·단위·기호·순서·복합운동 묶음을 보존한다. `+`, `/`, 괄호, 끝의 `+`도 의미 있는 내용으로 취급한다.
- `DV Press`, `Sled Mode`, `FMCTP`, `BTP`, `SBL`을 사용자 확인 없이 교정하거나 풀어쓰지 않는다. 원문에 없는 운동을 추가하지 않는다.
- 4~6행, 긴 운동명, 제목 길이 변화에 맞춰 글자 크기·줄바꿈·간격을 자동 조절한다. 맞지 않는다고 운동행을 삭제하지 않는다.
- 같은 클래스에 새로운 메모를 넣어도 디자인 계열·색·서체·장식은 유지한다. 내용 길이에 필요한 배치만 조정한다.
- 운동 한 행을 수정하거나 색을 바꿀 때 다른 행과 확정된 디자인을 다시 생성하지 않는다. 색·글씨·배치 변경은 가능한 한 로컬에서 처리해 추가 AI 호출을 줄인다.
- 제목·시간·운동 내용·장식을 각각 편집할 수 있다. 로고나 `突破` 같은 서예 장식은 운동행으로 취급하지 않는다.
- 편집 미리보기, PNG, 수업 화면에서 내용·배치·브랜드가 일치한다. 저장한 수업에는 당시의 템플릿 버전과 적용 스타일을 보존한다.
- 이미지 전용 제작에 실행 타이머 설정을 필수로 넣지 않는다. 시간을 적은 이미지를 만들기 위해 코치가 타이머 운영 규칙을 모두 입력할 필요는 없다.

AI의 스타일 제안과 참고 디자인 분석은 헤더·본문·번호·섹션·장식·여백·서체 등 편집 가능한 구성으로 저장한다. 검수한 구성요소와 레이아웃 규칙을 조합해 표현력을 확보하고, 실제 글자 측정과 안전 영역 검사로 출력 품질을 보장한다. 특정 이미지처럼 보이도록 만드는 일과 안정적으로 반복 제작하는 일을 함께 검증한다.

1~2를 먼저 제공해 반복 작업을 바로 줄이고, 그 기반 위에 3A·3B를 확장한다. 3A와 3B는 템플릿 계약과 렌더러가 정해지면 병렬 개발할 수 있다. **최종 제품 범위에는 기본 디자인·AI 새 디자인·원하는 템플릿 반영의 세 경로가 모두 포함된다.**

주간 일괄 생성은 현재 서버·DTO·컨트롤러의 ‘정확히 한 장’ 계약과 사용량 정책을 함께 바꿔야 한다. 장수나 날짜는 실제 입력을 따르며 목표 이미지 7장을 모든 요청의 출력 개수로 고정하지 않는다.

## 목표 사례와 검수 세트

첫 고객 사례는 [10/5 ~ 10/10 WOD 미리보기](https://blog.naver.com/stationd01/224429784859)의 월~토 이미지와 사용자 제공 돌파 포스터다. 블로그 게시일은 2026년 10월 2일이다. WOD 6장은 3840×2160, 돌파 스크린샷은 2316×1262이며 이미지 내용과 크기를 변경하지 않고 저장했다.

| 첫 고객 사례 | 보존할 특징 |
| --- | --- |
| WOD 6장 | 상단 컬러 띠, 왼쪽 제목, 오른쪽 UNBROKEN·STRENGTH·MAX·SWEAT·HYROX 분류, 시간 문구, 번호 배지, 총 32개 운동행 |
| 돌파 1장 | 클래스명 돌파와 세션 제목 Brick Session 구분, 검정·붉은색·흰색, 세리프 서체, 무번호 4행, 별도 서예 장식 |

이 7장만으로 전체 센터 지원을 검증하지 않는다. **로고·참고 이미지 없는 새 센터, 기존 로고·대표색이 있는 센터, AI에게 새 스타일을 요청한 센터, 자체 템플릿을 가져오는 센터**를 별도 평가 시나리오로 둔다. 이는 추가할 검수 시나리오이며 현재 확보한 다른 실고객 사례를 뜻하지 않는다.

각 센터에서 같은 디자인에 서로 다른 길이와 행 수의 메모를 반복 입력한다. 내용 정확성, 디자인 일관성, 첫 제작 시간, 다음 제작 시간, 손으로 배치를 수정한 횟수를 확인한다. 고정 렌더러 검사와 실제 AI 응답 검사는 분리하고, AI 응답은 동일 입력을 여러 번 생성해 변동을 본다.

## 성공 지표

**핵심 지표는 운동 메모 준비 후 수업 이미지를 사용할 때까지 걸리는 수정 포함 작업 시간**이다. 🔵 현재 기준선은 미측정이다. 🔶 제안 목표는 같은 작업의 중앙값 50% 단축이며, 0단계 코치 평가 후 확정한다.

- 다음 수업 제작에서 디자인을 처음부터 다시 설정하는 작업이 없어야 한다.
- 첫 고객 목표 7/7의 제목·분류·시간 문구·전체 36행·수치·조건·기호·순서를 보존한다.
- 기본 디자인 경로에서는 로고·참고 이미지·디자인 지식 없이 첫 결과를 만들 수 있어야 한다.
- 새 스타일 3안은 내용은 같고 디자인은 구별되어야 한다. 선택 후 반복 제작에서는 같은 스타일을 유지해야 한다.
- 1920×1080 기준 기존 본문 최소 36px·제목 48px 정책을 유지하고, 4K 표시·모바일 미리보기·타이머 표시 전후에 겹침과 잘림이 없어야 한다.
- 손으로 글자 크기·줄바꿈·위치를 고친 횟수, 내용 수정 수, 저장 후 재수정 비율을 측정한다.
- 초안 복원·취소·계정 전환·테마 전환·늦은 AI 응답·저장 실패·재시도에서 확정한 내용과 다른 센터의 데이터가 영향을 받지 않아야 한다.

현재 프리미엄·예산·캐시·실패 환급 보호를 유지한다. 새 스타일 제안, 참고 이미지 분석, 일괄 생성은 호출 목적과 사용량을 구분해 기록한다. 🔵 별도 횟수 차감이나 요금 정책은 아직 정하지 않으며 제품 정책 결정 항목으로 남긴다. 기본 디자인 선택과 로컬 편집은 AI 호출이 없어도 가능하게 한다.

## 구현 의존성과 후속 범위

기존 `storeId`를 센터 식별자로 활용하고 서버가 소유자와 연결을 확인한다. `ownerUid`는 기존 접근권한·과금 주체와 연결한다. 센터 ID가 없는 레거시 계정의 연결·테마 이관 경로를 마련한다. 직원 초대·다지점 권한체계 전체는 별도 범위로 두고, 이번에는 현재 소유자 모델에서 센터별 디자인을 올바르게 분리한다.

기존 운영 브랜드와 슬라이드·스타일 라이브러리를 재사용한다. 새 템플릿 계약은 버전과 자산 참조를 갖고, 저장한 수업은 적용 시점의 디자인을 보존한다. 구버전 표시를 위한 PNG fallback을 유지한다. 생성 캐시는 콘텐츠·생성 계약·관련 센터 맥락을 구분하고, 단순 디자인 편집은 로컬 렌더링으로 처리한다.

돌파 원본의 서체와 제작 도구는 사용자가 알지 못한다. 이를 추가 입력의 전제조건으로 삼지 않고, 제공받은 원본 PNG를 변경 없이 보관해 한자·배경·변경하지 않은 글자를 재사용한다. 제목은 원본 그대로 고정하며, 변경한 시간·운동 글자에만 대체 서체를 적용하고 원본 영역 안에서 크기를 측정한다. 가독성을 유지할 수 없거나 4행을 넘으면 저장 전에 수정 안내를 제공한다. 기본 디자인의 초기 계열과 AI 제안 범위도 디자인 검수로 확정한다. 현재 모델 교체나 별도 이미지 생성 모델 도입을 먼저 결정하지 않고, 반복 제작과 스타일 표현의 실제 실패 원인을 측정해 선택한다.

실행 타이머 연결은 후속 개선으로 다룬다. 이미지에 표시할 시간 문구와 실행 설정을 분리하고, `30s move`, E2MOM의 적용 범위, 단위 없는 Time Cap, 마지막 휴식·반복 수를 임의 확정하지 않는다. 현재 미지정 시간이 기본 60초가 되는 변환은 명시적인 미확정 상태로 개선해야 한다. 이미지 제작 완료를 위해 이 타이머 결정을 강제하지 않는다.

후속 검증에서는 WOD 6장의 원본 파일 해시와 1920×1080 출력 픽셀 일치, 한 행 수정·마지막 행 제거 시 나머지 픽셀 보존, 행 수 초과 시 저장 차단을 확인했다. 돌파를 포함한 렌더러 검사 19개, 내용 생성·원본 전환·초안·페이지/키보드 검사 39개를 통과했고 원본 노출 빌드에서도 디자인 선택 검사 10개를 통과했다. `flutter analyze`는 오류·경고가 없다.

하단 네비게이션 후속 수정에서는 원본 노출 빌드로 관련 화면 검사 21개를 통과했다. 작은 화면·가로 화면·태블릿에서 상단 추가 액션, 초안 복원, 키보드 입력, 탭 전환 시 수업 내용·디자인 설명 유지, 템플릿 선택과 도구 진입 시 생성 요청 0회를 확인했다. 실제 시뮬레이터에서 제목 옆 beta와 상단 +, 하단 네 탭, 스타일 제안/이미지로 시작 화면을 확인했다. 신규 디자인 callable이 배포되지 않은 운영 환경에서는 생성 이용 가능 여부 조회가 실패하며, 이번 UI 수정에서 서버를 배포하지 않는다.

목표 이미지 보관, 이번 브랜치 범위의 기능 구현, 로컬 자동 검증과 실제 AI 응답 평가는 진행했다. 시뮬레이터는 운영 진입점으로 리빌드했고 기존 사용자 계정 로그인과 기존 워크아웃 표시를 확인했다. 후속 빌드에서 `수업 이미지 생성` 페이지 진입·뒤로 가기·초안 복원·컬러 beta·원본 미리보기를 확인했다. 운영 서버·규칙은 변경하지 않았다. 코치 작업 시간 단축은 아직 측정하지 않았다.
