# main 배포 실패 수정

대상 커밋: `dce24bf` · 확인일: 2026-09-21

웹, Android, iOS 워크플로가 모두 Flutter 테스트에서 같은 5개 실패로 중단됐다. 스토어 업로드 및 Firebase 규칙/웹 배포 단계에는 도달하지 않았다.

## 원인과 수정

STA-16 리팩토링으로 로컬 재생·슬라이드 미리보기가 계정 설정 저장소를 조회하게 됐지만, 두 테스트 파일에서 새 의존성을 제공하지 않았다.

- `workout_finish_test.dart`: 로컬 자연 종료/수동 종료에서 설정을 읽지 못해 재생 화면에 진입하지 못했다.
- `slide_library_replacement_test.dart`: 세 가지 화면 크기에서 실제 Firebase 초기화 오류에 따른 Riverpod 재시도 타이머가 남았다.

계정 소유자를 확인하고 호출을 기록하는 메모리 설정 저장소를 테스트에 주입했다. 설정 해석과 화면 코드는 실제 구현 그대로 실행한다. 테스트 제외·실패 무시·재시도 억제는 하지 않았다.

로컬 재생만 설정을 조회하고 원격 재생은 기존 스냅샷을 사용하는지, 미리보기에 공통 문구/볼륨이 적용돼도 원본 워크아웃 값은 유지되는지 검증을 추가했다. 앱 실행 코드와 DB 규칙은 수정하지 않았다.

## 검증

- 수정 전 실패 5개를 로컬에서 재현.
- 두 파일 8개 테스트 통과.
- Flutter 전체 276개 통과.
- Functions 전체 23개 통과.
- Dart 정적 분석 오류 없음, 전체 포맷 변경 없음.

이 문서의 로컬 검증 결과와 배포 성공은 별개다. main 병합 후 웹·스토어 워크플로 결과를 별도로 확인한다. 데이터 일괄 이관 도구는 실행하지 않는다.
