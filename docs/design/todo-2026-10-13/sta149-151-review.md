# STA-149 · STA-150 · STA-151 관리 화면 적용

2026-10-13. 기존 Oat Sage v5 테마와 실제 관리 위젯을 사용한다. `references/proposed-more.png`의 계정 요약 → 수업과 센터 → 시작과 소식 순서를 구현에 적용했다. 시안의 픽셀 색이나 화면 크기를 새로운 토큰으로 도입하지 않았다.

## 화면별 상태와 행동

| 화면 | 표시 기준 | 다음 행동 |
| --- | --- | --- |
| 홈 | 등록된 TV가 없으면 연결 안내, 등록되어도 모두 오프라인이면 오프라인 안내, 온라인 수는 응답 확인과 구분 | TV 탭에서 상태 확인, 수업 만들기·선택, 검색/폴더 조건 지우기 |
| 라이브러리 | 기존 카탈로그의 첫 로딩·부분 로딩·캐시와 오류·빈 목록·검색 없음 유지 | 빈 탭에서 수업/슬라이드/폴더 만들기, 검색 지우기, 모든 폴더 보기, 오류 재시도 |
| 더보기 | 실제 계정 이름·사진 요약, 2개 그룹, 원래 6개 목적지 | 프로필, 매장 관리, 구독, 첫 수업, 예시 수업, 업데이트 |
| 프로필 | 편집 가능한 이름/사진에 별도 진입, 인증 조회 중/실패/확인 완료 구분 | 이름·사진 수정, 센터 정보 재확인, 구독 관리 |
| TV 목록 | 등록 대수/온라인 대수/최근 응답/송출 설정을 각각 표시. 조회 중에는 0대 또는 완료를 표시하지 않음 | TV 앱·인터넷 확인, 응답 번호 보내기, 이름/화면 맞춤/연결 해제 |
| 첫 TV 연결 | 앱 열기 → QR/6자리 코드 → 이름과 구역 → 무음 응답 번호 4단계 | 소유자 계정만 새 TV 등록, 수동 코드와 이 기기에서 연습 경로 유지 |
| 코드 입력 | 요청 중 입력과 재요청 잠금, 실패 후 코드 유지. 등록과 실제 TV 응답 확인을 별도 단계로 유지 | 만료 시 새 코드, 네트워크 확인, 소유자 확인, 플랜 한도 확인 |
| 진행 제어 | 수업명, 현재 슬라이드/전체, 일시정지/진행/운동 완료/명령 확인 중 | 기존 재생·이전/다음·스와이프·잠금·최소화·종료 유지 |

TV 활성화 한도에 도달하면 중지할 기존 TV를 사용자가 직접 선택한다. 선택 전에는 확인 버튼이 비활성이고 취소하면 요청하지 않는다. 명시한 ID만 `replaceDeviceIds`로 전달한다. Free/Plus 이름이나 `1`이라는 임계값으로 플랜을 추측하지 않고 서버 프로필의 `hasPlanDisplayPolicy`, `unlimitedDisplays`, `displayLimit`을 사용한다. 서버가 최종 허용 여부를 결정한다.

## 유지한 동작과 범위

- 매장 운영의 워크아웃 기본값·대기 화면·예약 재생·원격 관리·리포트 5탭은 `/operations` 상세에 유지했다. 이번 변경은 루트의 진입 구조와 상태 안내이며 운영 탭의 입력/데이터 모델은 바꾸지 않았다.
- 프로필 저장 중/실패 시 입력 유지와 미저장 이탈 확인, 계정 삭제의 재인증·삭제 영향·Apple/Google 구독 해지 안내를 유지한다.
- 라이브러리 편집 제한, 저장 충돌, 복제/폴더/삭제, 독립 복사본 삽입, 진행 중 수업과 검색/스크롤 유지 로직을 재사용한다.
- 사용자 슬라이드와 센터 로고, TV 캔버스/타이머 색, 연결·플레이어 프로토콜은 변경하지 않았다. 온라인이라는 사실을 화면 재생 성공으로 표시하지 않는다.
- 사용자 결정으로 별도 완료 처리한 과거 STA-24/25/31은 이 구현에 포함하지 않았다.

## 검증과 캡처

`test/management_journey_ui_test.dart`는 실제 화면과 격리된 Riverpod 데이터로 경로, 인증 조회 중, TV 조회/오프라인, 1대/3대 한도의 명시적 교체, 중복 연결 요청, 검색 재설정과 빈 수업 생성 경로를 검증한다. 관리 화면 6종을 320/390 논리 px, 글자 2배로 점검하며 주요 조작의 48px 영역과 스크롤 도달 가능성을 확인한다.

`tool/sta149_151_capture_test.dart`는 동일한 프로덕션 위젯을 논리 390×844, DPR 2로 렌더링한다. 일부 접근성 상태는 320×844·글자 2배다. 페이지에 실제 `MainNavigationDock`를 배치한 로컬 캡처 셸을 사용하며, 전체 라우터/실제 계정/TV는 연결하지 않는다. 실제 `Image.image` 제공자를 미리 디코딩하고 PNG를 이 문서와 같은 폴더에 저장한다. 로딩은 시간 제한 없이 정착을 기다리지 않고 정해진 프레임만 렌더링한다.

실행 결과: 기존 회귀 95개 통과, 새 관리 UI 22개·모드 선택기 1개·캡처 1개는 최종 실행 24/24 통과. 대상 14개 Dart 파일 정적 분석은 이슈 없음. 처음 큰 글자 검사에서 발견한 TV 모드 선택기의 가로 넘침은 관리 화면에서만 세로 배치하도록 수정했다. 공통 선택기의 기본 방향은 가로로 유지해 TV 화면의 배치를 바꾸지 않는다.

회귀 대상은 `display_settings`, `display_removal`, `display_verification`, `profile_save_feedback`, `account_management_section`, `library_management`, `home_workout_list`, `home_workout_loading`, `workout_control_panel`, `main_navigation` 테스트다. 기존 95개는 첫 실행 모두 통과했고 새 테스트의 비교/스크롤 fixture와 접근성 넘침 수정 후 새 테스트 전체를 재실행했다. 최종 명령은 다음과 같다.

```sh
flutter test --no-pub test/management_journey_ui_test.dart test/device_mode_toggle_test.dart tool/sta149_151_capture_test.dart
```

실제 기기의 카메라 권한, 실제 TV의 확인 번호/응답/송출 전환, 스토어 구독 구매·해지는 이 로컬 UI 캡처로 검증했다고 간주하지 않는다. 출시 실기기 검수에서는 코드 만료/네트워크 단절/카메라 권한 거부 후 수동 입력, Free 1대와 Plus 3대의 한도 초과 및 명시 선택 교체, 오프라인 TV의 재접속과 실제 ACK 뒤 성공 표시를 각각 확인한다.
