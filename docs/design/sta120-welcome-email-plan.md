# CloudBoard 웰컴 메일 기획

신규 가입자가 첫 수업 준비와 샘플 체험으로 이동하도록 안내한다. STA-120의 결과물은 이 기획과 [HTML 시안](sta120-welcome-email.html)이며, 실제 발송 기능과 배포는 별도 작업이다. 2026-10-13 기준.

## 문구와 화면

- 제목: **CloudBoard에 오신 것을 환영합니다!**
- 미리보기 문구: 첫 수업 안내와 타이머, CloudBoard에서 함께 준비해 보세요.
- 제목 영역: **첫 수업을 함께 준비해 볼까요?**
- 인사: 이름이 있으면 “{이름}님, CloudBoard에 오신 것을 환영합니다!”, 없으면 “안녕하세요, CloudBoard에 오신 것을 환영합니다!”
- 본문: “수업을 준비하는 시간은 줄이고, 회원에게 더 집중할 수 있도록. 수업 안내와 타이머를 한 화면에 담아 첫 수업을 준비해 보세요.”
- 주 버튼: **시작하기**
- 보조 제목: **첫 수업을 가볍게 시작해 보세요**
- 보조 본문: “샘플 수업으로 안내 화면과 타이머의 흐름을 먼저 살펴보세요. 어떤 수업을 만들지 천천히 정해도 괜찮아요.”
- 보조 버튼: **샘플 수업 체험하기**
- TV 보조 문구: “수업이 준비되면 앱의 ‘TV 연결’에서 큰 화면으로 함께할 수 있어요. 지원 기기와 같은 계정의 연결 상태를 먼저 확인해 주세요.”
- 끝인사: “궁금한 점이 있으면 이 메일에 답장해 주세요. CloudBoard 팀”
- 하단: “CloudBoard 가입에 따른 첫 이용 안내 메일입니다. 예상하지 못한 메일이라면 답장으로 알려주세요.”

이름은 텍스트로 이스케이프하고 공백 정리 후 최대 30자로 표시한다. 회사명·결제·플랜·전화번호는 넣지 않는다. 요금제 전환과 독립적으로 사용할 수 있도록 체험 기간과 유료 혜택도 넣지 않는다.

흰 배경, 최대 본문 폭 560px, 좌우 최소 20px, 제목 30px/1.45, 본문 16px/1.8. 검은 주 버튼과 테두리 보조 버튼, 1px 구분선으로 시선을 나눈다. 브랜드 워드마크는 텍스트로 구현해 이미지 차단에도 읽힌다. 클릭 영역은 48px 이상이며 이미지·외부 폰트·JavaScript 없이 사용한다. HTML 시안은 이메일의 table 구조와 인라인 스타일을 사용한다. 개인화 없는 시안이 기본이며 발송 구현 시 같은 내용의 text/plain 파트도 제공한다.

## 버튼 목적지와 기기별 진입

| 버튼 | 확정 목적지 | 동작 |
| --- | --- | --- |
| 시작하기 | https://cloud-board-stationd.web.app/ | 현재 웹 앱. 로그인 상태에 따라 홈 또는 로그인·온보딩으로 진입 |
| 샘플 수업 체험하기 | https://cloud-board-stationd.web.app/#/explore | 가입 없이 샘플 탐색. 현재 go_router의 /explore와 일치 |

모바일·데스크톱 모두 HTTPS 웹 경로를 사용한다. 설치를 강제하거나 미구현 universal/app link를 약속하지 않는다. 인증 토큰과 이메일을 URL에 넣지 않는다. TV 전용 공개 가이드 경로가 없으므로 별도 TV 링크는 이번 메일에서 제외하고 보조 문구만 둔다. 배포 전 실제 발송 템플릿에서 두 주소를 iOS Safari·Android Chrome·데스크톱으로 확인한다.

## 발송 대상과 시점

서비스 제공용 안내로 가입 완료 후 1회 발송한다. 가입 트랜잭션이 커밋되고 서버가 확인한 이메일 주소가 있는 시점에 outbox를 등록한다. 로그인이나 휴대전화 인증 반복, 유료 플랜 선택에는 발송하지 않는다. Google·Apple·이메일 가입 모두 동일한 canonical 사용자 ID로 중복을 묶는다. 익명·TV 기기·미인증 이메일·이메일 미제공 계정은 건너뛰며 가입 과정은 정상 진행한다. 이메일 인증이 나중에 완료된 신규 계정은 그때 한 번 대상이 된다.

발송 기능 활성화 시각 이후 생성된 계정만 대상이다. **기존 회원 소급 발송은 하지 않는다.** 가입 직후 첫 사용을 돕는 목적이므로 전체 온보딩 완료까지 기다리지 않는다. 메일 실패는 가입 성공을 취소하지 않는다. Apple 비공개 릴레이 주소는 Apple에 발신 도메인과 주소를 등록하고 전달을 검증한 뒤 활성화한다.

## 중복과 실패 처리

서버 outbox의 고유 키는 `welcome-v1:{canonicalUserId}`다. 생성은 원자적으로 한 번만 가능하며 전송 시 `welcome/v1/{outboxId}`를 Resend idempotency key로 보낸다. 이메일 변경·반복 로그인·동시 OAuth 콜백·재시도는 같은 outbox를 공유한다. 템플릿 버전을 바꿔도 자동 재발송하지 않는다.

상태는 pending → sending(lease) → sent/providerAccepted, 또는 retry/manualReview/suppressed. 같은 시도의 수신자와 본문 스냅샷을 재사용한다. API의 성공 응답은 발송 접수이며 실제 전달 여부는 서명 검증한 webhook으로 구분한다. timeout/429/5xx만 1분·5분·30분·2시간 간격으로 최대 5회(최초 포함) 재시도하고 모두 최초 시도 24시간 안에 끝낸다. 이미 접수됐는지 불명확한 상태가 24시간을 넘으면 자동 재발송하지 않고 운영 확인으로 전환한다. 영구 4xx, bounce, complaint는 자동 재시도하지 않는다. Resend의 idempotency 보존은 24시간이므로 앱의 영구 발송 원장을 함께 유지한다. [Resend idempotency 문서](https://resend.com/docs/dashboard/emails/idempotency-keys)

원장에는 사용자 ID, 템플릿 버전, 상태, 시도 횟수, provider ID와 시각을 저장한다. 로그에는 메일 본문·이메일·이름·키를 출력하지 않는다. 계정 삭제 시 대기 작업을 취소한다. 운영 지표는 접수·전달·실패·중복 방지 건수로 시작하며 열람 추적은 사용하지 않는다.

## 테스트와 실제 발송 준비

현재 소유 도메인이 없으므로 실제 가입자 발송은 비활성 상태다. 기본 Resend 도메인은 계정 소유 이메일로만 테스트할 수 있다. [Resend 테스트 도메인 제한](https://resend.com/docs/knowledge-base/403-error-resend-dev-domain)

| 항목 | 테스트 | 실제 발송 |
| --- | --- | --- |
| From | CloudBoard <onboarding@resend.dev> | 소유·인증한 도메인의 발신 주소 확정 필요 |
| To | vividxxxxx@gmail.com 고정 | 서버에서 확인한 신규 가입자 주소 |
| Reply-To | vividxxxxx@gmail.com | 같은 주소 유지 가능 |
| 내용 | 가상 이름 또는 이름 없음 | 가입자 이름 선택 적용 |
| 활성화 | 명시적인 테스트 발송 작업에서만 | 도메인·DKIM/SPF·수신 확인 후 별도 배포 |

도메인 검증은 소유권과 SPF/DKIM 준비를 포함하며 DMARC도 설정한다. [Resend 도메인 문서](https://resend.com/docs/dashboard/domains/introduction) 테스트 모드에서 실제 가입 이벤트를 본인 주소로 전달하지 않는다. 테스트 자격 증명·발신 설정은 서버에만 보관하고 production과 분리한다.

발송 구현 완료 기준: 두 CTA 실제 진입, Gmail/Apple Mail 및 320px/390px/desktop 읽기, 이름 없음·긴 이름·HTML 문자, 중복 가입 이벤트, worker 재시도/timeout, 24시간 경계, 삭제 계정, 잘못된 webhook, bounce/complaint, 테스트 To 제한, 비활성 플래그를 검증한다. 이번 PR에는 발송 트리거·API 키·실제 메일 전송을 포함하지 않는다.
