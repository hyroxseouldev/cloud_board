# STA-162 저장 이미지와 버전 적용

이번 변경은 일반 템플릿의 공통 렌더러를 갱신한다. 수업 내용·운동 순서·횟수·시간·색상과 저장된 명시적 굵기/기울임은 바꾸지 않는다. 새 수업/카탈로그/시작 예시에만 완화된 스타일 기본값을 적용한다. StationD 월~토·Brick 원본 이미지와 업로드된 사진의 글자는 대상에서 제외하며, 타이머와 세트 표시 크기도 유지한다.

| 사용 환경 | 적용 시점과 결과 |
| --- | --- |
| 업데이트된 관리 앱의 선택 카드·편집·라이브러리·연습 | 지원하는 일반 디자인은 `WorkoutSlideCanvas`가 공통 painter로 직접 그리므로, 예전 PNG가 남아 있어도 새 크기로 표시한다. |
| 업데이트된 TV 앱 | 지원하는 일반 디자인을 직접 렌더링하므로 새 크기를 사용한다. 재생 중인 수업의 내용/타이밍 snapshot은 그대로 유지한다. |
| 기존 수업 재저장 | renderer fingerprint의 `v1`→`v2` 변경으로 예전 PNG 재사용을 거절하고 새 PNG를 생성·업로드한 뒤 수업에 기록한다. 다음 변경 없는 저장은 새 PNG를 재사용한다. |
| 수업 복제·라이브러리 슬라이드 삽입 후 저장 | 같은 저장 경로를 거친다. 이전 버전 또는 다른 수업 범위의 이미지 힌트는 재사용하지 않는다. 라이브러리 항목 자체를 수정해 저장할 때도 공통 painter로 PNG를 만든다. |
| 이전 앱/TV가 해당 디자인 계약을 지원하는 경우 | 그 앱에 내장된 이전 painter가 직접 그리므로 예전 크기가 유지될 수 있다. 새 PNG를 저장하는 것만으로 이 화면을 바꿀 수 없으며 앱/TV 업데이트가 필요하다. |
| 이전 앱/TV가 디자인 계약을 지원하지 않아 PNG fallback을 쓰는 경우 | 전달받은 저장 PNG를 표시한다. 최신 앱에서 재저장하고 새 수업 snapshot을 받은 후 새 이미지가 반영된다. 이미 실행 중인 snapshot이나 내려받은 이전 PNG는 소급 변경되지 않는다. |
| 이미 가져와 편집한 시작 예시 | 반복 가져오기는 서버의 기존 수업을 반환한다. 새 초기 샘플로 덮어쓰지 않으며, 기존 복사본도 최신 앱의 공통 크기 정책을 사용한다. 사용자가 저장한 부제와 스타일은 유지한다. |

앱을 켤 때 전체 계정의 수업/라이브러리를 다시 쓰는 마이그레이션은 추가하지 않는다. 이전 이미지 URL도 삭제하지 않아 기존 snapshot과 복구 데이터가 유지된다. 생성·업로드 실패 시 저장 오류를 반환하며 원래 수업은 변경하지 않는다.

`tool/firebase/supported-clients.json`의 고정 소스를 대조한 대표 사례는 다음과 같다. 이는 배포 바이너리 실행 검수가 아닌 소스 계약 확인이다.

| 고정 클라이언트 / 소스 | 일반 디자인 표시 경로 |
| --- | --- |
| Android production 52 / `c85167e` | `imageSource` 표시. 최신 앱에서 만든 새 PNG를 새 snapshot으로 받아야 반영된다. |
| iOS 548 · Android closed 58 / `c54588c` | stationd-v1/v2는 이전 자체 렌더러, studio-v1은 저장 PNG fallback. |
| iOS 553 · Android/TV 65 · Web 142.1 / `a865307` | studio-v1 포함 이전 자체 렌더러 사용. 앱 업데이트 필요. |
| 1.1.0 iOS 554 · Android/TV 68 · Web 159.1 / `9289366` | studio-v1 포함 이전 글자 크기의 자체 렌더러 사용. 앱 업데이트 필요. |

앱 제공 시작 예시의 “예시 · 자유롭게 수정하세요”는 화면 안내로 이동한다. 기존 사용자 수업에서 같은 문자열이 부제로 저장되어 있어도 출처를 확정할 수 없으므로 임의 삭제하지 않는다. 수정한 수업의 부제를 지우려면 편집 화면에서 명시적으로 변경한다.

### PNG fallback에서 발견한 기존 타이머 색상 한계

밝은 배경의 시작 예시를 PNG만으로 재생하면, 자동 타이머 색상 계산이 `designTextColor`를 사용하지 않아 운동 숫자와 ring이 흰색으로 보이는 기존 문제가 있다. develop `322d985`에도 같은 코드가 있으며 production52 및 review548/closed58의 고정 소스에서도 해당 조건을 확인했다. 저장 PNG의 운동 글자/번호는 일치하며, 이 제한을 색상 덮어쓰기로 숨기지 않고 원본 캡처를 보관했다. [STA-163](https://linear.app/clyrdev/issue/STA-163)에서 자동색·명시색·구버전 전달 정책을 별도로 해결한다. 현재 지원하는 일반 디자인의 직접 렌더링에서는 기존 타이머 색상·크기·위치를 유지한다.

## 검증 범위

- 현재 클라이언트의 공통 painter, PNG 생성, fingerprint 재사용, 수업 복제/라이브러리 삽입 저장 경로를 자동 검증한다.
- 알 수 없는 디자인 계약은 저장 PNG를 보존하는 기존 회귀 테스트를 실행한다. 이전 클라이언트의 자체 렌더링과 fallback 차이는 코드 계약에 근거한 적용 정책이며, 모든 과거 배포 바이너리를 실행했다는 뜻이 아니다.
- 1920×1080/4K와 휴대폰·태블릿 크기는 로컬 Flutter 캡처로 검증한다. 실기기/센터 TV의 시청 거리 가독성은 사용자 요청에 따라 후속 확인으로 남긴다. 실제 TV 크기·거리·결과는 아직 측정하지 않았다.

관련 구현: `slide_design_renderer.dart`, `workout_slide_canvas.dart`, `workout_storage_data_source.dart`, `workout_repository_impl.dart`, `account_slide_editor_repository.dart`.
