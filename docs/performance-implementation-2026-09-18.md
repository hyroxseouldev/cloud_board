# 성능 개선 2·5·6 반영 기록

## 기능과 데이터 보존

워크아웃 편집·복사·검색·폴더·목록 페이지·예약·재생 기능은 유지한다. 재생 중 편집 잠금도 유지한다. 기존 `workouts` 원본 문서는 이동하거나 삭제하지 않았다.

- **2 예약 확인:** 로컬 예약 중 실행 시각이 도래한 미실행 항목이 있을 때만 서버의 재생 상태를 조회한다. 해당 예약이 없으면 기존 시간당 최대 180회의 상태 조회가 0회가 된다.
- **5 목록 경량화:** `users/{uid}/workoutSummaries`에 이름·폴더·이미지·모듈 수·시간·수정 시각을 저장하고, 상세는 ID로 읽는다. 전체 검색과 폴더 개수를 유지하기 위해 경량 목록은 모든 페이지를 읽는다. 문서 읽기 횟수가 94% 줄어드는 변경은 아니다. 오프라인 사용을 위해 누락되거나 변경된 상세는 동시 2개씩 백그라운드 캐시한다. 최초 캐시 준비 시 전체 상세 다운로드는 여전히 발생한다.
- **6 재생 데이터 분리:** 변경하지 않는 워크아웃 내용은 `playbackSnapshots/{sessionId}`에 한 번 저장하고 `activeSession`에는 작은 상태와 참조를 기록한다. 상태 명령은 기존 리비전 검증을 유지한다. 완료 후 7일 지난 스냅샷은 정리하되 현재 세션이 참조하는 스냅샷은 보존한다.

## 운영 DB 반영

2026-09-18 프로젝트 `cloud-board-stationd`의 계정 4개, 워크아웃 6개를 백업한 뒤 요약 문서를 생성하고 원본과 필드별로 대조했다. 기존 세션 2개에는 스냅샷 사본만 추가했다. 기존 `activeSession` 값은 변경하지 않았다. 당시 완료되지 않은 세션은 0개였다.

백업: `/Users/sunmkim/.codex/backups/cloud-board/performance-v2-20260918-final` (계정별 JSON, 디렉터리 권한 700·파일 600). 원본 Firestore 타임스탬프는 JSON의 seconds/nanoseconds 표현으로 보관되므로 복구 시 Timestamp 변환이 필요하다.

실제 데이터의 JSON 크기 비교:

| 항목 | 기존 | 개선 구조 | 감소 |
|---|---:|---:|---:|
| 워크아웃 목록 | 15,556 B | 997 B | 93.6% |
| 재생 상태 | 6,940 B | 879 B | 87.3% |

이는 프로토콜 오버헤드를 제외한 데이터 크기이며 실제 응답 시간·앱 프레임·요금 개선율을 측정한 수치는 아니다. 재생 상태 수치는 기존 두 세션을 새 구조로 표현한 비교다. 운영 중인 기존 세션을 새 구조로 강제 변환하지 않았다.

Firestore·Realtime Database 규칙 및 `syncWorkoutCatalog`, `cleanupPlaybackSnapshots` 함수를 배포했다. 구버전 앱이 워크아웃을 저장해도 서버 트리거가 최신 원본을 읽어 요약을 동기화한다. 트리거는 재시도·중복·순서 역전에 안전하도록 구성했다. `catalog/schema` 완료 표시는 관리자만 생성하며, 표시 없는 계정은 앱이 기존 목록 경로로 처리한다.

## 앱 적용 순서

클라이언트 코드는 이 작업공간에 반영되었다. 설치된 모바일·TV 앱이나 스토어 배포본이 자동 업데이트된 것은 아니다. 컨트롤러 앱과 연결된 모든 TV 앱에 새 빌드를 설치해야 한다. 모든 등록 TV(오프라인 포함)가 `playbackProtocol >= 2`를 보고한 경우 다음 재생부터 분리 구조를 사용하며, 하나라도 구버전이면 기존 구조로 시작한다. 기존 세션은 계속 기존 구조로 처리한다.

TV 능력 확인은 구버전 컨트롤러 앱까지 식별하지 않는다. 여러 컨트롤러를 사용하는 계정은 컨트롤러를 모두 업데이트한 뒤 새 재생을 시작해야 한다.

## 검증

Flutter 전체 회귀 테스트 261개 통과, 정적 분석 문제 0건을 확인했다. Firestore/RTDB 에뮬레이터 보안 규칙 및 이전 검증, Functions 단위 테스트 12개, Android와 iOS 네이티브 재생 명령 검증도 통과했다. 경량 목록 검색·페이지·상세 로딩·중복 실행 방지·오프라인 준비·예약 조회 생략·v1/v2 재생·리비전 충돌·스냅샷 불변성과 정리를 포함한다.

이전 스크립트는 `functions/scripts/migrate-performance-v2.mjs`이며 기본은 읽기 전용이다. 실제 적용은 `--apply --backup-dir <새 디렉터리>`가 필요하고 기존 백업 파일을 덮어쓰지 않는다.
