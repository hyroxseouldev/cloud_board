# 2.1.1 Firebase / Dart TLS 보안 패치

## 범위

사용자 요청은 **보안 패치를 develop에 반영하는 것까지**다. main 병합,
개발/운영 태그 생성, Firebase 배포, TestFlight/Play 업로드는 포함하지 않는다.
`2.1.1+8`과 `release-notes/current.json`은 출시 후보 정보이며 공개된 업데이트가
아니다. 기존 설치 앱에는 향후 별도 승인된 재빌드·배포·설치가 필요하다.

개발 기준은 `b5c3c6cbb0cc0352743cbf66486b07193a69d1a0`이다. 직전 실제
iOS/Android 업로드는 2.1.0의 `f9edab461a148e68c995c1d97d160226bf1334c2`이며,
두 커밋의 파일 내용은 같다. 기존 로컬 작업 폴더의 미커밋 변경은 포함하지 않는다.

## 근거와 변경

2026-11-04에 다음 공식 공지와 공개 패키지 내용을 확인했다.

- [Firebase eMudhra 보안 조치](https://firebase.google.com/support/guides/compromised-emudhra-intermediate-ca)
- [Dart SDK 보안 공지 GHSA-frr6-h895-5pxp](https://github.com/dart-lang/sdk/security/advisories/GHSA-frr6-h895-5pxp)

Android/TV는 Dart의 TLS 인증서 검증 수정, iOS는 Firestore의 내장 인증서
수정이 각각 필요하다. 메일은 CloudBoard의 실제 데이터 유출을 입증하는 자료가 아니다.

| 구성 요소 | 2.1.0 | 이번 후보 |
| --- | --- | --- |
| Flutter / Dart | 3.47.0 / 3.13.0 | 3.47.8 / 3.13.7 |
| cloud_firestore | 6.9.0 | 6.10.2 |
| firebase_core | 4.14.0 | 4.15.2 |
| Firebase Apple SDK | 12.18.0 | 12.19.3 |

기존 주요 버전 계열의 보안 수정판을 사용한다. SwiftPM의 Firebase 버전은
각 플러그인이 정확한 버전으로 지정하므로 Auth, Storage, Database,
Crashlytics, Functions, Remote Config도 같은 Apple SDK 12.19.3을 요구하는
호환 버전으로 함께 맞췄다. 앱에 포함되는 8개 Firebase 플러그인의
`Package.swift`에서 이 버전을 확인했다.

`pub get`만으로 남겨진 이전 Auth 하위 인터페이스 9.0.7은 새 플러그인의
`migrateCurrentUser` 매개변수와 호환되지 않아 실제 테스트 컴파일이 실패했다.
Firebase 관련 하위 패키지만 추가 해석하여 Auth interface 9.1.0,
Auth web 6.3.0, Core web 3.12.0으로 맞춘 뒤 검증했다.
무관한 패키지의 일괄 업그레이드는 수행하지 않았다.

`.fvmrc`, Dart/Flutter 최소 버전, `pubspec.lock`, 두 iOS `Package.resolved`를
함께 갱신한다. iOS 잠금 파일은 Flutter의 설정 생성과 Xcode의 실제 의존성
해석 결과다. 하트비트·타이머·음성 예약 로직, 서버 코드, 보안 규칙은 수정하지 않는다.

## 검증

macOS에서 위 Flutter/Dart 버전과 이번 후보 변경을 사용했다. 최종 커밋과
실제 검사 대상의 관계는 PR의 `검증한 커밋` 항목에 기록한다.

- `dart analyze lib test`: 통과, 진단 없음.
- 관련 Flutter 유닛/위젯 테스트 141개: 통과. 하트비트, 준비/복구,
  로그인, 저장 오류/복구, 카운트다운과 Android 음성 예약, TV 수명 주기를 검사했다.
  이 결과는 fake/mock 경계를 포함하며 실제 TV 성능 측정이 아니다.
- 실제 FlutterFire Chrome 저장 probe 1개: 통과. 로컬 Auth/Storage/Functions/Firestore로
  로그인, 이미지 저장, 실제 앱 repository → callable → 저장/재조회,
  수정·복원·사용량·로그아웃 경계를 검사한다. Node 22 / Java 21 환경의
  demo 프로젝트만 사용한다. 이 검사는 네이티브 TLS 공격 재현이 아니다.
- Flutter iOS `--config-only` 및 Xcode `-resolvePackageDependencies`: 통과.
  프로젝트와 워크스페이스 모두 Firebase Apple SDK 12.19.3으로 해석된다.
- 업데이트 소식/버전 검사 6개: 통과. 후보 소식을 실제 게시하지 않는다.
- 전체 CI, 네이티브 IPA/AAB 빌드·서명, 실기기 실행, 운영 서비스 검증,
  취약 인증서를 이용한 공격 재현: 미실행. 별도 배포 단계에서 필요한 검증은 남아 있다.

주요 실행 명령:

```sh

  test/display_heartbeat_recovery_test.dart test/display_heartbeat_policy_test.dart \
  test/display_preparation_recovery_test.dart test/display_preparation_retry_test.dart \
  test/device_pairing_recovery_test.dart test/display_mode_flow_test.dart \
  test/workout_save_diagnostics_test.dart test/workout_preflight_dialog_test.dart \
  test/email_auth_test.dart test/apple_auth_test.dart test/workout_recovery_test.dart \
  test/playback_audio_cues_test.dart test/android_workout_cues_test.dart \
  test/countdown_audio_test.dart test/tv_playback_lifecycle_test.dart
dart analyze lib test
# Node 22, JAVA_HOME=Java 21, FLUTTER_BIN=Flutter 3.47.8
node functions/test/run-workout-save-callable-emulator.mjs --flutter-client
flutter build ios --config-only --flavor development --debug --no-codesign \
  --dart-define=FIREBASE_ENV=development
xcodebuild -resolvePackageDependencies -workspace ios/Runner.xcworkspace \
  -scheme development -clonedSourcePackagesDirPath build/ios/SourcePackages
node --test tool/update-news/news.test.mjs
git diff --check
```

로컬 증거는 원래 작업 폴더의
`output/releases/2.1.1-security-2026-11-04/`에 보관한다. PR의 필수
`firebase-required`는 인계 기록·공백 검사이며 위 실제 검사나 전체 CI를
대신하지 않는다.
