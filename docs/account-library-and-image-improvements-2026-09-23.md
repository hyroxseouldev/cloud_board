# 계정 라이브러리·즐겨찾기·이미지 저장 개선

## 적용 범위

1. 슬라이드 라이브러리와 저장한 스타일을 계정 단위로 동기화한다.
2. 플러스는 즐겨찾기 **등록** 3개, 프리미엄은 무제한으로 처리한다. 일반 라이브러리 항목 수는 제한하지 않는다.
3. 큰 이미지 최적화, 중복 업로드 재사용, 최대 3개 병렬 업로드, 저장 진행 안내를 추가한다.

TV 준비 상태 안내와 워크아웃 동시 편집 충돌 처리는 이번 작업에 포함하지 않는다.

## 데이터 및 호환성

- 기존 워크아웃 문서, 공통 설정, 재생 세션 형식은 변경하지 않는다.
- 새 Firestore 경로:
  - `users/{uid}/slideTemplates/{id}`
  - `users/{uid}/slideStyles/{id}`
  - `users/{uid}/libraryState/index` — 즐겨찾기 개수 집계
- 항목은 `schemaVersion: 1`, `value`, `deleted`, `updatedAt`으로 저장한다.
- 클라이언트는 본인 계정 데이터만 읽을 수 있다. 쓰기는 `updateSlideLibrary` callable에서만 처리한다.
- 서버는 인증 UID와 요청 계정 일치, 탈퇴 잠금, 항목 형식, 즐겨찾기 제한을 검사한다.
- 변경한 항목만 전송하므로 다른 기기에서 추가한 항목을 전체 목록 저장으로 지우지 않는다. 같은 항목이 다른 기기에서 변경되었다면 오래된 내용의 덮어쓰기를 거절한다.
- 즐겨찾기 개수와 항목 변경을 같은 트랜잭션에서 처리하여 동시 요청으로 제한을 초과하지 못하게 한다. [Firestore 트랜잭션 문서](https://firebase.google.com/docs/firestore/manage-data/transactions)

### 기존 기기 자료 이전

- 해당 계정의 기존 `templates.{uid}` / `styles.{uid}`만 읽는다. 다른 계정 또는 `local` 자료를 자동으로 가져오지 않는다.
- 인라인 이미지를 Storage에 먼저 올린 뒤, 25개 단위로 항목을 이전한다.
- 이미 존재하는 ID와 삭제 표시가 있는 ID는 건너뛴다. 늦게 업데이트한 다른 기기의 자료가 삭제한 항목을 되살리지 않는다.
- 전부 성공한 경우에만 이전 완료 지문을 저장한다. 중간 실패 후 다시 열면 재시도한다.
- 원래 SharedPreferences 자료는 지우거나 덮어쓰지 않고 복구용으로 남긴다.
- 플러스에서 기존 즐겨찾기가 3개를 초과하면 초과분의 별표만 해제한다. 슬라이드 내용은 모두 일반 라이브러리에 보존한다.
- 구버전 앱은 계속 기기 저장소를 사용한다. 계정 동기화는 업데이트한 앱끼리 적용된다. 동일 ID가 구버전에서 수정된 경우 기존 클라우드 항목을 자동 덮어쓰지 않으며 로컬 원본은 남는다.
- 최초 이전 및 신규 저장·삭제·즐겨찾기 변경에는 인터넷이 필요하다. 서버 확인 없이 변경을 저장 완료로 표시하지 않는다. 이전 완료 후 읽기 캐시는 Firestore SDK의 플랫폼별 동작을 따른다.

## 즐겨찾기 동작

- 저장 창에서 즐겨찾기 여부를 선택한다. 편집 화면의 빠른 삽입 칩은 즐겨찾기만 표시한다.
- 칩의 삭제 버튼은 **즐겨찾기 해제**로 동작한다. 원본 삭제는 라이브러리에서 별도로 한다.
- 라이브러리 복제는 일반 항목으로 생성하여 원치 않는 즐겨찾기 추가를 피한다.
- 플러스의 네 번째 등록 요청은 서버가 거절하고 기존 즐겨찾기 해제/프리미엄 안내를 보여준다.
- 기존 legacy 요금제는 서버 메타데이터에 맞춰 이전 제한 정책을 유지한다.
- 프리미엄에서 플러스로 전환하면 `syncSlideLibraryPlan` 서버 트리거가 3개만 즐겨찾기로 유지하고 초과분의 별표만 해제한다. 내용은 모두 유지하며, 해제 후 다시 원하는 항목을 등록할 수 있다. 늦게 도착한 이벤트가 최신 프리미엄 업그레이드를 취소하지 않도록 현재 권한을 트랜잭션 안에서 재확인한다.

## 이미지 처리

- 새 슬라이드 및 카운트다운 배경 선택 시: JPEG 긴 변 2560px, 정적 PNG 긴 변 3840px를 넘는 경우 축소한다.
- JPEG 품질 90, PNG 형식/투명도 유지. GIF·WebP 애니메이션과 APNG는 변환하지 않는다. 작은 이미지는 원본 바이트를 유지한다.
- 변환 결과가 원본보다 크면 원본을 사용한다. 입력 40MB, 디코딩 5,000만 화소, 최종 업로드 10MB 미만을 확인한다.
- 업로드 시에도 같은 정책을 적용하므로 기존 인라인 배경도 최적화할 수 있다. 기존 원격 URL 이미지는 재다운로드하거나 다시 변환하지 않는다.
- CPU 디코딩은 한 번에 하나만 처리하여 태블릿 메모리 사용량을 제한한다. 네트워크 업로드는 최대 3개까지 겹쳐 실행한다.
- 동일 배경이 여러 슬라이드/카운트다운에 사용되어도 한 번만 업로드한다. 계정·워크아웃·이미지 해시 기반 경로를 재사용하며 성공한 파일은 실패 후 재시도에서도 다시 올리지 않는다.
- 실패 시 진행 중인 업로드가 끝난 뒤 오류를 반환하고 새 작업은 시작하지 않는다. 워크아웃 저장은 모든 이미지 업로드 후 진행한다.
- 저장 버튼 주변 상태/툴팁에 `이미지 1/3 저장 중`을 표시한다. 전체 화면 로더를 추가하지 않는다.

## 검증 및 배포

- Flutter 전체 테스트 315개 통과(라이브러리 이전·계정 분리, 편집/복구, 이미지 형식/크기, 동시 업로드/실패 포함).
- Node 단위 테스트 25개 통과.
- Firestore 에뮬레이터: 동시 즐겨찾기 4개 중 3개만 성공, 이전/초과 즐겨찾기 보존, 삭제 항목 재이전 방지, 동일 항목 충돌, 멱등 재시도, 플랜 전환, 계정 간 접근 차단, 직접 쓰기 차단, 탈퇴 잠금 통과.
- Flutter 정적 분석 및 웹 release 빌드 통과.
- 웹 배포 액션에 Java 21 및 위 에뮬레이터 검사를 추가했다.
- **서버 함수와 Firestore 규칙을 앱보다 먼저 배포해야 한다.** 기존 main 배포 액션이 함수/규칙을 먼저 배포하고 웹 앱을 배포한다. 이번 작업에서는 실서비스 배포를 실행하지 않았다.
- 실제 두 기기 로그인 후 업로드/동기화와 모바일 사진 선택은 배포 후 실기기 확인이 남아 있다.

에뮬레이터 검증 명령:

```sh
firebase emulators:exec --config firebase.deletion-test.json --only firestore --project demo-cloudboard-library 'node functions/test/slide-library-emulator.mjs'
```
