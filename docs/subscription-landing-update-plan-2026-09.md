## 1. 목적과 기본 방향

기존 랜딩을 방문한 매장 대표가 실제 사용 장면과 가격을 이해하고 체험을 신청하도록 만든다. 첫 연결과 수업 사용을 마친 고객은 같은 사이트에서 월 구독을 시작하고 관리한다.

핵심 경로는 **영업·소개 링크 → 랜딩 → 체험 신청 → 기기 확인·첫 연결 → 14일 사용 → 월 구독 → 다음 달 갱신**이다. 9월에는 운영자가 연결을 돕는 방식을 우선하고, 검증한 기기 조합부터 직접 시작하는 경로를 추가한다.

타깃은 한 운영 계정에서 동일한 그룹 수업을 화면 1~3대로 진행하는 기능성 운동·그룹 PT 매장 대표다. 첫 유입은 직접 영업, 지인 소개, 시연 후 링크 공유를 중심으로 가정한다. 홈페이지 유입량만으로 유료 고객 목표를 달성한다고 가정하지 않는다.

사이트의 주 행동은 ‘14일 체험 신청’이다. 로그인은 기존 고객용 보조 동선으로 둔다. 화면 확장 문의와 세팅 대행은 해당하는 고객에게 추가 선택지로 제공한다.

2026-09-18 실제 사이트의 텍스트와 요금 영역 화면을 확인했다. 로컬 `landing-preview/dist/index.html`에도 같은 핵심 구조가 있다. 로컬 파일이 실제 배포 원본 저장소인지까지 확인한 것은 아니다.

가격은 이번 수익화 시나리오에 따른 제안이며 공개 사이트에는 아직 반영하지 않았다. 이미 약속한 기존 파일럿 조건이 있으면 개별 유지·안내하고 자동 변경하지 않는다.

## 3. 공개 상품과 정책 제안

| 상품 | 표시할 가격 | 내용 |
|---|---:|---|
| 무료 체험 | 14일 0원 | 첫 디스플레이 연결 후 시작 동의, 카드 불필요, 자동 유료 전환 없음 |
| CloudBoard Pro | 월 39,000원 / 매장 | 단일 운영 계정, 등록 디스플레이 최대 3대, 동일 수업 전송, 현재 편집·타이머·제어·대기 화면 |
| 초기 세팅 대행 | 149,000원 / 1회 / 선택 | 고객 제공 운동 프로그램 3개 입력, 배경·색상 적용, 원격 연결·교육 60분, 수정 1회 |

표시 금액은 부가세 포함 제안이다. 구독·세팅 카드와 결제 요약에 동일하게 표시한다. 장비 및 방문 설치는 별도다. 계정의 컨트롤러 기기는 디스플레이 등록 한도에 포함하지 않는다. 화면마다 독립적인 수업을 실행하는 상품으로 설명하지 않는다.

셀프 설정 안내와 기본 원격 연결 지원 20분을 구독 도입 과정에 포함한다. ‘설치 지원’을 모두 유료 세팅으로 오해하지 않게 구분한다. 세팅 대행은 총 작업 2시간 범위로 운영하고, 자료 확인·범위 합의·검수 완료 후 별도 청구한다. 랜딩에서 바로 149,000원을 결제시키거나 구독 주문에 기본 체크하지 않는다.

첫 3개 파일럿의 무료 세팅은 운영자가 지정하는 개별 조건이다. 실시간 잔여 수량을 관리하지 않는 ‘선착순 3곳’ 배너로 공개하지 않는다. 연간 결제, 평생 할인, 무제한 저장, 팀 권한, AI 운동 생성, 예약 자동 실행은 이번 공개 상품에서 제외한다.

## 4. 기존 랜딩의 최종 섹션과 문구

### 4.1 헤더

로고 / 제품 소개 / 시작 방법 / 요금제 / FAQ / 로그인 / [14일 체험 신청]

로그인 상태에서는 ‘로그인’을 ‘내 구독’으로 바꾼다. 신규 고객의 주요 버튼은 페이지 내 신청 폼으로 이동한다. 모바일에서는 메뉴를 줄이고 화면 하단에 체험 신청 버튼을 두되 폼 입력 중에는 숨긴다.

### 4.2 첫 화면

**제목**

> 수업 진행은 화면에.
> 코치는 회원에게.

**설명**

> 우리 매장의 운동 순서와 타이머를 TV에 띄우고,
> 휴대폰·태블릿으로 수업을 제어하세요.

**주 버튼:** 14일 체험 신청

**버튼 아래:** 카드 등록 없이 체험 · 연결 완료 후 14일 · 체험 후 월 39,000원

첫 화면의 사진 자리에 휴대폰과 연결 TV가 함께 보이는 실제 시연을 우선 배치한다. 영상은 직접 재생하는 30~60초 분량, 소리 없이도 이해되는 자막, 포스터 이미지를 갖춘다. 영상이 없으면 현재 앱 캡처와 예시 표시를 사용하고 재생 버튼처럼 보이는 가짜 컨트롤을 두지 않는다.

### 4.3 실제 사용 장면

기존 제품 화면 탭을 유지하고 탭별 설명을 결과 중심으로 정리한다.

| 탭 | 제목 | 설명 |
|---|---|---|
| 수업 진행 | 필요한 순간, 손에서 바로 제어하세요. | 수업을 시작하고 잠시 멈추고 다음 순서로 이동하세요. |
| 슬라이드 편집 | 평소 쓰던 운동 프로그램을 화면으로. | 운동 설명과 이미지, 운동·휴식 시간을 수업에 맞게 구성하세요. |
| 디스플레이 연결 | 매장 화면에 같은 수업을 보여주세요. | QR 또는 연결 코드로 등록한 화면에 운동과 시간을 표시하세요. |

화면은 현재 배포 후보와 일치하는 캡처로 교체한다. 이미 제거된 브리핑·완료 화면이나 아직 검증하지 않은 제어 동작을 최신 기능으로 소개하지 않는다.

### 4.4 시작 방법

**제목:** 우리 매장에서 써보고 결정하세요.

1. **체험 신청:** 매장과 연락받을 방법을 알려주세요.
2. **기기 확인·화면 연결:** 사용할 기기를 확인하고 첫 수업을 준비합니다.
3. **14일 실제 수업:** 연결을 마친 뒤 체험을 시작하고, 계속 사용할 때 구독하세요.

기존의 ‘만들기→연결→시작’은 제품 사용 설명으로 남길 수 있으나, 가입부터 도입까지의 3단계와 구분한다. 지원할 수 있는 범위가 검증되기 전 ‘TV만 있으면 됩니다’, ‘3분 설치’ 같은 표현은 사용하지 않는다.

### 4.5 매장에 맞춘 화면

### 4.9 FAQ 문구

- **체험은 언제 시작하나요?** 신청일이 아니라 첫 디스플레이 연결을 마치고 체험 시작을 확인한 시점부터 14일입니다.
- **체험이 끝나면 자동 결제되나요?** 아닙니다. 체험에는 카드가 필요 없고, 계속 사용할 때 직접 구독을 신청합니다. 유료 구독 이후에는 별도 동의한 월 갱신 조건이 적용됩니다.
- **지금 쓰는 TV로 가능한가요?** 호환 실행 기기와 네트워크가 필요합니다. TV·연결 기기 모델을 확인한 뒤 가능한 구성을 안내합니다. 장비는 별도입니다.
- **화면마다 다른 수업을 할 수 있나요?** 현재 기본 상품은 같은 수업을 최대 3개 등록 화면에 전달합니다.
- **설치를 꼭 맡겨야 하나요?** 직접 설정할 수 있고 기본 연결 안내를 제공합니다. 프로그램 입력과 교육까지 맡길 때 선택형 세팅을 신청하세요.
- **운동 프로그램도 제공하나요?** 매장이 제공한 운동 프로그램을 화면으로 구성하는 도구입니다. 운동 처방이나 영상 콘텐츠 구독은 포함하지 않습니다.
- **구독은 어떻게 해지하나요?** 내 구독에서 다음 갱신을 중단할 수 있으며, 이미 결제한 이용 기간의 종료일을 확인할 수 있습니다. 환불 안내는 별도 정책에서 확인하세요. 이 문구는 해당 기능 공개 후 노출합니다.

| 필요한 도움 | 선택 | 직접 설정 / 초기 세팅 상담 / 아직 모름, 기본은 아직 모름 |
| 사용 기기·문의 | 선택 | 짧은 텍스트, 모델명을 몰라도 접수 가능 |
| 신청 처리용 개인정보 안내·동의 | 실제 처리 기준 확정 후 적용 | 목적·항목·보관 기간·문의처 표시. 광고 수신과 묶지 않음 |

폼 제출 중에는 중복 제출을 막고 입력값을 유지한다. 서버에 저장이 완료돼야 ‘신청이 접수되었습니다’를 표시한다. 접수 ID, 다음 단계, 실제 운영 가능한 응답 기한을 보여준다. 응답 목표는 1영업일로 제안하되 운영 시간을 확정한 뒤 공개한다.

오류 문구: ‘신청이 완료되지 않았습니다. 입력한 내용은 유지되어 있습니다. 다시 시도하거나 아래 문의처로 연락해주세요.’ 네트워크 재시도로 접수가 중복되지 않게 처리한다. 메일 앱만 연 경우 접수 완료라고 안내하지 않는다.

운영자는 신규 접수 알림과 목록을 확인하고 담당 상태·다음 연락일을 기록한다. 알림 발송 실패와 신청 저장 실패를 구분한다. 9월에는 신청 목록과 상태 변경만 가능한 최소 관리 화면이면 충분하다.

영업으로 먼저 확보한 매장도 같은 목록에 수동 등록한다. 반복 신청은 기존 건과 연결하고, 신청 연락처가 앱 로그인 이메일과 다를 수 있으므로 연락처 일치만으로 구독 계정을 자동 결합하지 않는다.

## 7. 체험·유료 구독 흐름

### 체험 시작

신청 접수 → 운영자가 기기·수업 방식 확인 → 앱 설치와 기존 계정 로그인 → 첫 디스플레이 연결 → 실제 시작 확인 → 서버에 체험 시작·종료 시각 기록.

14일은 시작 시각부터 14×24시간으로 계산하고 고객에게 한국 시간의 종료 날짜와 시각을 표시하는 안으로 한다. 최초 유효 시작 시각은 기기를 다시 연결하거나 앱을 재설치해도 초기화하지 않는다. 장애로 인한 기간 연장은 운영자가 사유와 새 종료 시각을 기록해 처리한다.

### 첫 유료 결제

첫 버전에서는 체험 종료 후 첫 결제를 진행하는 단순한 방식으로 시작한다. 체험 중에는 종료일과 월 금액을 보여주고, 사용하지 않은 체험 기간을 소멸시키는 조기 결제는 추가하지 않는다. 기존 파일럿·무료 혜택이 있는 고객은 합의한 종료일을 먼저 반영한다.

로그인 → 매장명·계정 확인 → 월 39,000원 상품 확인 → 첫 이용 기간·다음 결제 예정일·월 자동 갱신 동의 → 결제수단 등록·결제 → 서버 확인 → 이용 권한 반영 → 앱에서 이용.

월 구독 주기는 결제 사업자의 달력 기준을 따르며 월말·윤년 처리까지 결제 전 표시와 서버 기록이 일치해야 한다. 첫 결제일을 기준으로 월 갱신하고 단순히 매 30일로 안내하지 않는다.

### 결제 화면

- 구매할 매장과 이용할 앱 계정을 함께 표시한다.
- ‘오늘 결제 39,000원’, ‘매월 39,000원’, 다음 결제 예정일을 표시한다.
- 장비와 선택형 세팅 비용이 포함되지 않음을 표시한다.
- 유료 구독의 자동 갱신·해지·환불 안내를 제시하고 명시적으로 동의받는다.
- 최종 버튼: ‘월 39,000원 구독 시작하기’.
- 결제 성공 화면으로 돌아왔다는 이유만으로 이용 권한을 부여하지 않는다.

세팅 대행은 별도 주문·검수·1회 청구로 관리한다. 구독과 합쳐 첫 결제 188,000원을 기본값으로 만들지 않는다. 1회 결제 내역은 월 반복 매출에 포함하지 않는다.

### 구독 관리 상태

| 상태 | 고객에게 보여줄 정보 | 행동 |
|---|---|---|
| 연결 전 | 연결 후 체험이 시작됩니다 | 시작 가이드 / 연결 도움 |
| 체험 중 | 종료 날짜·시각, 남은 기간 | 앱 사용 / 도움 요청 |
| 체험 종료 | 체험이 끝났습니다. 계속 사용하려면 구독하세요 | 월 39,000원 구독 |
| 결제 확인 중 | 결제 결과를 확인하고 있습니다 | 상태 다시 확인 / 지원; 중복 결제 유도 금지 |
| 구독 중 | 플랜·금액·다음 결제일·등록 화면 수 | 결제수단 / 내역 / 구독 해지 |
| 갱신 중단 예약 | 다음 결제 없음, 이용 가능한 종료일 | 구독 계속하기 |
| 갱신 실패 | 실패 안내·유예 종료일 또는 이용 제한 안내 | 결제수단 변경 / 재시도 |
| 이용 종료 | 새 수업 시작 제한, 보관 정책 안내 | 재구독 |

해지는 로그인 후 ‘구독 해지’ → 종료일 확인 → ‘다음 결제 중단’으로 처리한다. 이유 설문은 선택이고 연락을 해야만 해지할 수 있게 만들지 않는다. 구독 해지·결제 환불·계정 삭제는 서로 다른 처리로 안내하되, 계정 삭제 시 미래 청구가 남지 않도록 연동한다.

진행 중인 수업은 체험 만료·구독 만료로 갑자기 중단하지 않고 종료까지 유지한다. 이후 새 수업 시작에 권한 검사를 적용한다. 만료 즉시 콘텐츠를 삭제하지 않는다. 데이터 보관 기간과 실패 시 유예·재시도 횟수는 공개 전에 확정한다.

## 8. 운영자가 사용할 최소 기능

초기에는 한 관리 화면에 체험 신청과 구독 상태를 함께 조회한다. 공개 랜딩과 별도로 관리자 권한을 검사한다.

- 신청: 접수·연락 예정·시연·기기 확인·체험·유료·종료 단계, 다음 행동일.
- 계정: 연락처와 별개로 검증한 앱 계정 연결, 매장명, 기기 조합.
- 체험: 시작·종료·실제 사용 횟수·마지막 수업 시각. 사용 데이터가 없으면 운영자가 확인해 입력.
- 결제: 실제 수납·갱신·환불·실패 상태와 결제 사업자 식별자, 세팅 대행 별도 구분.
- 후속 일정: 체험 3일·7일·11일·14일, 첫 결제 후 7일, 갱신 예정.
- 예외: 기간 연장 사유·담당자·시간 기록. 일반 사용자가 플랜·한도·기간을 수정하지 못하게 함.

9월에는 알림을 자동 대량 발송하기보다 운영자가 후속 연락 일정을 확인해 직접 처리한다. 마케팅 수신 동의와 신청 처리 연락을 구분한다.

## 9. 구현 요구사항과 완료 기준

기존 페이지를 업데이트할 프레임워크와 실제 배포 저장소를 확인한 뒤 구현한다. 정적 랜딩은 유지할 수 있지만 신청 저장·인증·결제·권한 관리는 서버가 필요하다. Firebase를 쓰는 앱과 계정을 연결하고 결제 사업자는 계약·원화 월 자동결제·취소/환불·운영 조건 확인 후 선택한다.

필수 기능:

1. 신청 저장, 중복 제출 방지, 실패 복구, 운영자 알림과 접근 제한.
2. 앱·웹 공통 로그인 및 매장·구독의 소유 계정 확인.
3. 검증된 서버만 구독 상태·한도·이용 기간을 쓰도록 보호. 현재 필드 존재를 유료화 완료로 간주하지 않는다.
4. 결제 검증·웹훅 중복 및 순서 역전 방어·누락 복구·권한 동기화.
5. 새 수업 시작과 디스플레이 등록 한도를 서버에서 확인.
6. 갱신 중단·실패·환불·계정 삭제와 결제 및 권한 연결.
7. 결제 정보는 사업자의 안전한 등록 흐름 사용, 카드 원문 직접 저장 금지.

검수 시나리오:

- [ ] 랜딩·FAQ·약관·결제 화면의 39,000원 및 체험 조건 일치.
- [ ] 서버 저장 실패 시 접수 성공 표시가 나오지 않음.
- [ ] 스마트폰에서 폼 입력·오류 확인·접수까지 완료 가능.
- [ ] 앱 기존 계정으로 웹 로그인 후 같은 디스플레이·체험 상태 표시.
- [ ] 계정 생성만으로 체험 시간이 소진되지 않음.
- [ ] 결제 성공·실패·취소·중복 클릭·서버 응답 지연에서 청구·권한 일관성 유지.
- [ ] 고객이 자기 구독 정보만 조회·변경할 수 있음.
- [ ] 해지 후 다음 갱신 중단, 남은 이용 기간 유지.
- [ ] 만료·해지·결제 실패로 진행 중인 수업이 끊기지 않음.
- [ ] 키보드로 탭·FAQ·폼을 사용 가능, 오류가 필드와 연결되고 읽기 가능.
- [ ] 기존 #pricing 링크와 개인정보·계정 삭제 링크가 계속 동작.

웹 결제 제공과 앱 안에서 웹 결제를 유도하는 기능은 구분해 구현한다. Apple·Google 정책의 적용은 앱의 판매 대상·국가·배포 방식에 따라 확인해야 하며 B2B라는 이유만으로 예외를 확정하지 않는다. 2026-09-18 확인한 공식 근거: [Apple 결제 지침](https://developer.apple.com/app-store/review/guidelines/#other-purchase-methods), [Google Play 결제 정책](https://support.google.com/googleplay/android-developer/answer/10281818?hl=ko).

체험→유료 비율은 종료된 체험군끼리 비교한다. 원래 사업안의 접촉 200곳→체험 33곳→첫 결제 16곳은 전체 영업 목표이며 웹사이트 방문 전환율로 바꾸지 않는다. 직접 시연으로 얻은 고객도 출처를 남겨 중복 계산을 피한다.

매주 확인할 질문: 방문했는데 신청하지 않는가 / 신청했는데 연결하지 못하는가 / 연결했는데 수업에 쓰지 않는가 / 써봤는데 결제하지 않는가 / 결제했는데 재결제하지 않는가. 문제가 생긴 구간 하나를 먼저 개선한다.

분석 이벤트에는 이름·전화·이메일·자유 입력 문의·결제정보를 넣지 않는다. 최초에는 집계 중심으로 시작하고 필요한 이벤트만 수집한다.
