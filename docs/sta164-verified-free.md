# STA-164 · 휴대폰 인증 후 Free 활성화

로그인한 계정은 휴대폰 SMS 인증을 마쳐야 Free를 사용할 수 있다. 인증이 서버에 기록되면 Free를 자동으로 활성화한다. 별도의 Free 시작 버튼, 센터 설문 완료, 신규 Premium 체험 발급은 필요하지 않다. 공개 예시 탐색과 미리보기는 계속 제공한다.

## 적용 정책

| 계정 상태 | 결과 |
| --- | --- |
| 인증 기록 없음 | Free 비활성. 로그인이나 결제 이력만으로 활성화하지 않음 |
| 서버에 유효한 기존 인증 기록 있음 | 재인증 없이 재접속 시 활성화·권한 동기화 복구 |
| 신규 SMS 인증 성공 | Free 활성화. 신규 체험 시작·종료일을 만들지 않음 |
| 기존 체험 또는 유료 권한 유효 | 원래 권한과 만료일 유지. Free는 하위 대체 권한으로만 보관 |
| 유효한 상위 권한은 있지만 인증 기록 없음 | 기존 서비스 이용은 허용. Free를 활성화하거나 인증 완료로 표시하지 않음 |
| 기존 체험 또는 유료 권한 만료 | 인증 기록이 있는 경우에만 Free로 전환 |
| 인증은 저장됐지만 권한 반영 실패 | 성공 화면을 표시하지 않고 재조회·재시도로 복구 |

새 Free 권한은 STA-154의 기존 정책(TV 1대, 수업 7개, 저장 슬라이드 3개, 기본 브랜딩, AI 사용 없음)을 사용한다. 기존 유료 상품의 가격·한도·결제 내역은 변경하지 않는다. Free의 기존 타임스탬프 호환 값은 설치된 클라이언트를 위한 전송 형식이며 상품의 체험 종료일이 아니다.

관리자가 기존 체험에 부여하는 별도 연장은 이번 인증 보상 변경과 분리해 유지한다. 새로운 프로모션 정책이나 결제 변경은 도입하지 않는다.

## 인증과 권한의 근거

- 앱: 서버 전용 `users/{uid}/onboarding/progress.phoneVerified` 기록을 사용한다.
- 웹: 검증된 계정 연결에 속한 SQL 인증 기록만 서버의 `webGrant.phoneVerified`로 전달한다. 사용자가 입력한 프로필·이메일 일치만으로 인증을 이전하지 않는다.
- `onboardingFree`, `subscriptionEntitlements`, RTDB `subscriptionAccess`는 클라이언트에서 쓸 수 없다. 프로필에 임의의 `phoneVerified` 값을 써도 권한을 얻지 못한다.
- 인증 기록이 없는 Free 후보는 과거 marker, baseline, webGrant, RTDB에 남아 있어도 새 활성 권한으로 선택하지 않는다. 유효한 기존 상위 권한은 보존한다.
- 센터 정보는 서비스 개인화를 위한 별도 입력이다. 소유자가 확인된 서버 센터를 준비하되 설문 완료를 Free 활성화 조건으로 사용하지 않는다.

## 재시도와 구버전 호환

인증 처리·온보딩 조회가 동일한 멱등 활성화 경로를 사용한다. Firestore와 TV의 RTDB 권한 반영을 확인한 뒤에만 활성화 완료를 응답한다. 인증 기록을 남긴 직후 연결이 끊겨도 재진입 및 `syncVerifiedFreeAccess` 재처리로 복구한다. 중복 요청과 여러 기기의 동시 요청은 같은 등록 기록과 권한으로 수렴한다. 개발 환경 배포 목록에도 이 복구 함수를 포함한다.

구버전의 `startFree`와 `startTrial` 호출도 동일한 인증 조건을 적용한다. `startTrial`은 Free 활성화 호환 경로로 처리하며 새 Premium 권한이나 `onboardingTrials` 기록을 발급하지 않는다. `trialEligible`은 false, 신규 예상 체험 종료일은 0이다. 이미 발급한 체험 날짜는 표시·감사를 위해 보존한다.

## 배포 순서

1. 앱 Firebase backend와 companion backend를 함께 준비한다. SMS 인증, 구버전 호출, 기존 체험 유지, 웹↔앱 인증 공유, 권한 투영 실패 복구를 에뮬레이터에서 검증한다.
2. 개발 환경에서 양쪽 backend를 먼저 반영한다. 신규 인증 시 trial 기록이 생기지 않고 Free 권한 및 TV 권한이 일치하는지 확인한다.
3. 앱과 companion UI, 공개 랜딩 안내를 해당 backend 배포와 함께 반영한다. backend가 교체되기 전에 새로운 활성화 안내만 먼저 공개하지 않는다.
4. 기존 계정은 서버 인증 기록을 바탕으로 지연 전환한다. 인증 기록이 없는 계정을 일괄 인증 처리하거나 체험·유료 원장을 수정하지 않는다.

PR 검증은 로컬·CI 테스트와 화면 증거를 포함한다. 운영 배포와 실기기 SMS/스토어 결제 검증은 별도 단계다.

## 검증 기준

- SMS 오류·만료·중복 번호·삭제 잠금, 미인증의 Free/체험 우회 호출 차단
- 신규·기존 인증의 자동 활성화, 중복·동시 요청, 부분 실패 후 재조회 복구
- 기존 유료·체험 만료일과 저장 데이터 보존, 인증 없는 만료 계정의 Free 거부
- 앱→웹 및 웹→앱의 서버 인증 공유와 오래된 동기화 쓰기 방지
- 인증 대기·성공·오류 재시도 화면과 선택한 수업 진입 유지
- 클라이언트의 인증·권한 위조 차단 및 인증 전 TV 수업 거부
- 기존 Firebase 호환 테스트로 진행 중인 수업과 설치된 클라이언트 계약 유지 확인
