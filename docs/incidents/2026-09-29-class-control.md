## 코드에서 확인해 수정한 경로

- RTDB 연결 스트림은 건강한 연결에서도 처음 `false`를 보낼 수 있다. 첫 값만 검사하던 시작/명령 경로를 최대 6초 동안 `true`를 기다리도록 수정했다. 통신 실패는 `connection_timeout`으로 식별한다.
- 제어 명령의 expected revision이 느린 디스크 체크포인트에 의존했다. 수신 상태와 서버 ACK를 메모리에 즉시 반영하며, 오래된 revision 수신·늦은 ACK가 새 세션을 되돌리지 않게 했다.
- 여러 컨트롤러가 같은 revision을 조작하면 트랜잭션이 거절되는 것이 정상이다. 이를 일반 `Bad state`로 합치지 않고 `revision_conflict`, `session_changed`, `command_expired`, `status_changed`, `invalid_position` 등으로 구분한다. 충돌 후 서버 상태만 다시 확인하며, 오래된 조작은 자동 재전송하지 않는다.
- 수업 시작도 activeSession 트랜잭션으로 보호한다. 이미 실행/정지/준비 중인 다른 수업을 덮어쓰지 않는다. 6초 서버 만료 조건을 유지하고, 시작이 승인된 뒤 부가 이벤트 기록 실패를 수업 시작 실패로 오인하지 않는다.
- 음수/범위 초과 인덱스와 잘못된 슬라이드 자료를 명시적으로 거절한다. 화면의 모듈·스텝 접근에도 경계 검사를 적용한다. 이 방어 경로가 당일 RangeError의 정확한 발생 지점이었다고 단정하지 않는다.
- 기존 슬라이드 문서와 새 DTO의 선택 필드 기본값 차이가 허위 저장 충돌을 만들 수 있었다. 서버 비교 시 같은 기본값으로 정규화하며, 실제 내용 충돌은 계속 거절한다.
- 페어링 요청은 단일 실행, 20초 UI 대기 한도, callable 15초 한도, 원래 Firebase 코드·스택 보고를 적용했다. 시간 초과 후에도 기존 요청이 정리되기 전에는 중복 변경을 보내지 않는다. 온라인 복귀 등록은 트랜잭션으로 재연결 코드와 등록 상태를 확인해 해제된 기기를 되살리지 않는다.

동시 제어의 기본은 **서버 기준 시간 + 불변 수업 스냅샷 + revision별 사용자 의도 + 한 컨트롤러의 한 번에 한 명령**이다. UI를 맞추기 위한 매초 쓰기나 실패한 pause/seek의 무조건 재시도는 하지 않는다. 향후 현장 로그에서 충돌이 지속되면 ‘현재 조작자’ 표시와 짧은 조작 권한 임대를 검토할 수 있지만, 이번 변경에서는 여러 컨트롤러 사용을 금지하지 않는다.

## TV와 카운트다운

TV가 inactive/paused/hidden/detached로 바뀌면 로컬 비프와 예약된 비프를 취소하고 플레이어를 화면에서 내려 영상 재생도 중지한다. 원격 pause/complete를 보내지 않으므로 다른 디스플레이의 수업은 계속된다. resumed에서는 REST 기반 최신 상태 확인이 성공한 뒤에만 로컬 재생을 허용한다. 실패하면 음소거 상태와 재시도 화면을 유지한다. 모바일 정책은 유지한다.

카운트다운 조작은 다음처럼 구분한다.

| 버튼 | 동작 |
|---|---|
| 슬라이드 건너뛰기 | 현재 슬라이드 전체를 건너뛰고 다음 슬라이드로 이동. 마지막이면 종료. |
| 일시정지 / 계속 | 준비 시간의 남은 값을 유지하며 정지/재개. 정지 중 비프 중단. |
| 바로 시작 | 준비 시간을 종료하고 현재 구간의 전체 시간부터 한 번만 시작. |

Flutter와 Android 알림의 pause/resume 계산을 맞췄다. 빠른 중복 명령은 단일 실행 및 350ms 조작 제한으로 억제한다.

## 마지막 휴식 규칙과 배포 호환성

이번 ‘통일’은 **모든 세트 뒤에 설정된 휴식을 포함**하는 규칙으로 적용한다. 전체 수업의 마지막 세트도 동일하다. 휴식 0초는 별도 휴식 스텝을 만들지 않는다. 예: 10초 운동 + 5초 휴식 × 2세트 = 30초. 편집 합계, 목록 요약, 서버 요약, 타임라인, 미리보기, 실제 재생이 같은 규칙을 사용한다.

새 워크아웃/저장 문서의 `includeFinalRest` 기본값은 true. **이미 진행 중인 예전 스냅샷**에 필드가 없으면 false로 해석해 수업 도중 시간표가 변하지 않게 한다. 기존 목록 요약은 catalog의 `restPolicyVersion: 1` 마커를 이용해 다시 계산한다. 이전 앱이 사용하는 catalog version 2는 유지한다.

마지막 휴식이 있는 새 수업은 **연결된 TV/디스플레이가 playbackProtocol 3 이상이어야 시작**한다. 이전 TV가 다른 시간표로 재생하는 대신 업데이트 안내를 표시한다. 배포 후 컨트롤러와 TV를 함께 업데이트해야 한다. 기존 진행 중 수업은 그대로 유지한다.

## 라이브러리와 편집 화면

라이브러리는 ‘재사용하려고 저장한 슬라이드’ 모음이다. 내부 즐겨찾기 필터/토글을 제거하고 모든 저장 항목을 표시한다. 하단의 워크아웃·슬라이드·폴더 탭에서 각각 관리한다.

| 기존 자료 | 처리 |
|---|---|
| 워크아웃과 `folder` 문자열 | 원본 유지. 목록/편집/복제/삭제/폴더 이동 제공. |
| 저장 슬라이드, favorite=true/false | 모두 라이브러리에 표시. 이전 flag는 구버전 호환용으로 보존. |
| 기기 로컬 라이브러리 | 기존 계정 이관 경로 유지. 내용과 삭제 tombstone 보존, 초과 자료도 삭제/강등하지 않음. |
| 슬라이드 category | 폴더로 표시. 빈 폴더는 별도 account-owned 문서로 유지. |
| 폴더 이름 변경/삭제 | 서버 트랜잭션으로 워크아웃·요약·저장 슬라이드를 함께 갱신. 삭제 시 내용은 ‘폴더 없음’으로 이동. 440 쓰기 규모를 넘으면 분할 정리를 안내하며 부분 변경하지 않음. |

라이브러리에서 워크아웃에 넣을 때 새 ID의 **복사본**을 만든다. 원본 수정/삭제는 이미 넣은 슬라이드에 영향을 주지 않는다. 동일 저장 슬라이드의 동시 편집 충돌은 초안을 유지하며 최신 내용 불러오기/별도 복사 저장을 제공한다. 플러스의 신규 저장 한도는 저장 슬라이드 3개로 표시하며, 이미 보유한 초과 자료는 그대로 사용한다.

워크아웃 편집에서는 목록 마지막에 ‘슬라이드 추가’를 배치하고 우하단 FAB는 전체 워크아웃 실행으로 바꿨다. 미저장 변경을 먼저 저장한 뒤 기존 수업 준비 확인을 거쳐 실행한다. 저장 실패/취소 시 초안을 유지한다. 개별 슬라이드의 미리 재생은 편집 확인용이며 실제 원격 수업을 시작하지 않는다.

## 검증과 남은 현장 확인

자동 검증 결과와 배포 링크는 PR 및 각 Linear 이슈에 기록한다. 테스트는 초기 false 연결, 충돌 사유/revision, 지연된 체크포인트, 기존 스냅샷, 마지막 휴식, 카운트다운 경합, TV foreground gate, 오디오 큐 취소, 라이브러리 충돌/이관/권한, 작은 화면의 추가 버튼·탭을 다룬다.
