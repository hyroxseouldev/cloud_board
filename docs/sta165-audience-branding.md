# STA-165 · 관객용 화면의 CloudBoard 로고

STA-156의 대기화면 브랜딩을 확장한다. 가격, 저장 한도, 결제 상품, 기존 수업 자료는 변경하지 않는다. 관리자·코치의 조작 화면과 편집기에는 이 제품 로고 정책을 적용하지 않는다.

## 화면별 동작

| 화면 | Free | Plus/Premium |
| --- | --- | --- |
| 대기·시작 전 브리핑 | 심벌과 CloudBoard 표시 | 기존 제품 로고 설정으로 표시/숨김 |
| 시작 카운트다운 | 숫자와 분리한 하단 로고 영역 | 같은 설정 적용 |
| 운동·이미지·타이머·휴식·세트 전환·일시정지 | 작은 로고 고정 | 같은 설정 적용 |
| 완료 | 기존 대기화면으로 복귀 | 대기화면 설정 적용 |
| 명시적 검정 화면·영업 외 검정 화면 | 로고 없음 | 로고 없음 |

대기화면의 `showCloudBoardLogo` 원본 설정을 그대로 사용한다. 화면 문구 `brandL/brandR`, 문구 숨김, 이미지, 확대·잘라내기, 전체화면 설정과 제품 로고는 분리된다. 센터 로고를 수업 화면에 새로 추가하지 않는다. 원격 송출 설정의 `standby`는 대기화면이며 검정 화면인 `black`과 다르다.

공통 `AudienceLogoFrame`은 본문과 하단 로고 영역을 별도로 배치한다. 로고는 `DisplayViewport`의 이미지 확대·이동 밖에 있어 잘리지 않는다. 지원 범위가 확인된 화면은 유료 숨김 상태에서도 같은 하단 공간을 유지한다. 표시/숨김 변경은 로고만 바꾸며 타이머나 운동 본문의 위치를 흔들지 않는다. 정확한 크기·여백·대비와 장면별 캡처는 [디자인 검증](design/sta165/README.md)에 기록한다.

## 권한과 상태 전환

관객용 클라이언트는 서버 전용 RTDB `brandProjection`의 완전한 스냅샷을 읽는다. TV에 공개되지 않은 결제·구독 문서나 사용자가 편집할 수 있는 문구로 Free/유료 여부를 추정하지 않는다. 서버는 Free에 항상 로고 표시를 게시하고 유효한 Plus/Premium에는 보관된 설정을 적용한다. 유효한 체험·파일럿·레거시는 서버가 확정한 기존 권한을 보존한다.

- 권한 변경·설정 저장이 확인되면 현재 표시 중인 로고를 바로 갱신한다. 플레이어 키, 세션, 타이머 컨트롤러 및 수업 기록은 변경하지 않는다.
- 새 계약이 없는 계정은 기존 대기화면 동작을 유지한다. 수업 로고를 임의로 추가하지 않는다.
- 조회 실패·누락·알 수 없는 계약에서는 마지막으로 확인된 설정을 유지한다. 처음부터 확인된 설정이 없으면 unknown이며 Free로 해석하지 않는다.
- 새 설치의 첫 서버 응답이 이미 만료된 기록이면 새 설정으로 채택하지 않는다. 이전에 확인해서 보관한 캐시의 표시 유지와 구분한다.
- 캐시는 계정별로 구분한다. 로그아웃·TV 계정 재연결 중 이전 계정의 설정을 반환하지 않는다. 오래된 구독 revision이나 projection revision은 최신 캐시를 덮어쓰지 못한다.
- 연결 오류 뒤에는 15초 간격으로 다시 구독하며 재접속·앱 복귀 시에도 새로 읽는다. 저장 실패가 서버 조회를 막지 않는다.
- 캐시의 권한 기간이 지났다고 재생 중 로고를 바꾸지 않는다. 이 캐시는 표시 유지용이며, 새 수업을 시작할 권한은 기존 서버 접근 제어가 별도로 판단한다. 상품 설명은 기간이 유효한 새 계약이 확인된 경우에만 확장한다.

## 설정·상품 안내

앱 내 구독·브랜딩 설정은 해당 계정의 서버 투영을 확인한 뒤 “Free는 대기·수업 화면에 CloudBoard 로고 표시 / Plus부터 숨김 가능” 범위를 안내한다. 새 계약이 아직 적용되지 않았거나 확인되지 않으면 대기화면 범위를 안내한다. 센터 로고·배경 설정은 계속 대기화면에 한정한다고 설명한다.

웹 companion은 공개 출시 상태와 개별 계정 적용 상태를 구분한다. 일부 계정에만 적용하는 동안 공개 랜딩에 전체 출시로 안내하지 않는다. 기존에 숨긴 공개 기능 섹션과 가격은 그대로 유지한다.

## 적용과 검증 경계

앱 코드 배포만으로 정책을 전체 계정에 활성화하지 않는다. `plan-entitlements-v2`와 `appConfig/audienceBranding`의 명시적 활성화 조건을 모두 확인한다. 구버전 TV는 서버 데이터만으로 새 로고 컴포넌트를 얻지 못하므로 지원 빌드 배포 → 설치 상태 확인 → 선택 계정 활성화·재투영 → 실제 화면 확인 → 공개 안내 순으로 진행한다.

[서버 계약·지원 빌드 확인·재투영 절차](sta165-server-rollout.md)에 기본 읽기 전용 도구, 명시적 적용, 구버전·오프라인·롤백 기준을 기록했다. 이번 개발에서 운영 활성화·배포·스토어 업로드는 실행하지 않는다. 실제 TV 거리 가독성, overscan, 실기기 오프라인·재접속 검수는 사용자가 후속으로 진행한다.

자동 검증은 서버 권한·보안 에뮬레이터, Flutter 데이터·화면 회귀, Chrome 실행, CI 전체 검사를 포함한다. 장면 전환과 플랜 변경 테스트는 같은 플레이어 element를 유지하면서 남은 시간이 계속 감소하는지 확인한다. 캡처는 테스트 서버 상태를 주입한 실제 Flutter 렌더링이며 실기기 검증의 증거로 대신하지 않는다.
